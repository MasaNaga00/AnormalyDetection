## 1. なぜポアソン分布なのか

### 1.1 設定

ある機種の、ある部品について、1ヶ月に発生する交換件数を数える。これを $X$ とする。

- 市場に $N$ 台ある（$N$ は数千のオーダー）
- 各台がその月に故障する確率は $q$（非常に小さい。0.001 程度）
- 各台の故障は互いに独立とみなす

このとき $X \sim \text{Binomial}(N, q)$ である。

### 1.2 二項分布からポアソン分布へ

$N$ が大きく $q$ が小さいとき、平均 $\mu = Nq$ を固定したまま $N \to \infty$ とすると、
二項分布はポアソン分布に収束する。導出しておく。

$$P(X = k) = \binom{N}{k} q^k (1-q)^{N-k}$$

$q = \mu/N$ を代入する。

$$P(X = k) = \frac{N(N-1)\cdots(N-k+1)}{k!} \left(\frac{\mu}{N}\right)^k \left(1 - \frac{\mu}{N}\right)^{N-k}$$

$$= \frac{\mu^k}{k!} \cdot \underbrace{\frac{N(N-1)\cdots(N-k+1)}{N^k}}_{(a)} \cdot \underbrace{\left(1-\frac{\mu}{N}\right)^{N}}_{(b)} \cdot \underbrace{\left(1-\frac{\mu}{N}\right)^{-k}}_{(c)}$$

$N \to \infty$ で、

- $(a) = \prod_{j=0}^{k-1}\left(1 - \frac{j}{N}\right) \to 1$
- $(b) \to e^{-\mu}$（$\lim_{N\to\infty}(1+x/N)^N = e^x$）
- $(c) \to 1$

したがって

$$P(X = k) \to \frac{\mu^k e^{-\mu}}{k!}$$

これがポアソン分布 $\text{Poisson}(\mu)$ である。

**実務的な意味**: 台数が数千で故障率が0.1%程度という我々の状況は、この近似がほぼ完全に
成り立つ領域にある。以後、月次の交換件数はポアソン分布に従うとして扱う。

### 1.3 使う性質2つ

**(P1) 期待値も分散も $\mu$**

$$E[X] = \mu, \quad \text{Var}(X) = \mu$$

「平均10件なら標準偏差は $\sqrt{10} \approx 3.2$ 件」ということ。**件数が少ないほど
相対的なばらつきが大きい**（変動係数 $\sigma/\mu = 1/\sqrt{\mu}$）。5件と10件の差は
誤差の範囲だが、500件と1000件の差は明白に違う、という直感の根拠になる。

**(P2) 独立なポアソンの和はポアソン**

$X \sim \text{Poisson}(\mu_1)$、$Y \sim \text{Poisson}(\mu_2)$ が独立なら

$$X + Y \sim \text{Poisson}(\mu_1 + \mu_2)$$

証明は畳み込みで。$n = x + y$ として

$$P(X+Y=n) = \sum_{x=0}^{n} \frac{\mu_1^x e^{-\mu_1}}{x!}\cdot\frac{\mu_2^{n-x} e^{-\mu_2}}{(n-x)!} = \frac{e^{-(\mu_1+\mu_2)}}{n!}\sum_{x=0}^{n}\binom{n}{x}\mu_1^x \mu_2^{n-x}$$

二項定理より和は $(\mu_1+\mu_2)^n$ なので

$$P(X+Y=n) = \frac{(\mu_1+\mu_2)^n e^{-(\mu_1+\mu_2)}}{n!}$$

この性質のおかげで、**複数の月・複数の販社・複数の部番を合算しても、依然としてポアソンと
して扱える**。パネルを自由に集約できるのはこれが理由。

## 2. 露出（exposure）という考え方

### 2.1 件数そのものは比較できない

「機種Aで50件、機種Bで20件」だけでは何も言えない。Aの方が売れているだけかもしれない。
比較するには**母数**が要る。

$$\lambda = \frac{\text{交換件数}}{\text{露出}}$$

この $\lambda$ を**レート**と呼ぶ。「1台1ヶ月あたり何件交換が起きるか」。

### 2.2 露出の定義

我々のシステムでは

$$E = \sum_{\text{月 } t} F_t$$

$F_t$ はその月の累積販売台数（＝市場にある保有台数の近似）。単位は**台×月**（unit-months）。

12ヶ月分を足した $E$ が「延べ何台月ぶん観測したか」を表す。3000台を12ヶ月見れば
$E = 36000$ 台月。

### 2.3 期待件数

レート $\lambda$ で露出 $E$ なら、期待される件数は

$$\mu = \lambda E$$

そして観測件数は $X \sim \text{Poisson}(\lambda E)$。

**これが全ての基礎になる。** 以降、あらゆる比較は「$\lambda$ が等しいか」という問いに帰着する。

### 2.4 露出を二重に数えてはいけない

ここが実装で最も事故が起きやすい。具体例で示す。

ある機種が SF-CODE「SF-100」に部番を2つ持っているとする（nb=2）。

| | 部番 P-1 | 部番 P-2 | 合計 |
|---|---|---|---|
| 件数 | 30 | 20 | 50 |
| 保有台数 | 3000 | 3000 | **3000** |

件数は足してよい（性質P2）。しかし**保有台数は足してはいけない**。
同じ3000台に両方の部品が載っているのであって、6000台あるわけではない。

誤って足すと

$$\lambda_{\text{誤}} = \frac{50}{6000} = 0.0083, \qquad \lambda_{\text{正}} = \frac{50}{3000} = 0.0167$$

レートが**ちょうど半分**に潰れる。nb=1 の機種と比較すると、真に異常でも正常に見えてしまう。

`signal_b_peer.py` の `build_peer_units` が

```python
fm = (d.groupby(["biz","dev","ym","dist"])["fleet"].max()      # 月ごとに1回だけ
        .groupby(["biz","dev","ym"])["fleet"].sum())            # 販社は足す
```

としているのはこのため。**部番方向には max、販社方向には sum。**

## 3. 素朴な比較がうまくいかない理由

### 3.1 やりたいこと

2つのレートを比べたい。

$$\lambda_1 = \frac{C_1}{E_1} \quad \text{（対象）}, \qquad \lambda_2 = \frac{C_2}{E_2} \quad \text{（比較対象）}$$

帰無仮説は $H_0: \lambda_1 = \lambda_2$。「差はない」を疑い、棄却できたら異常と判定する。

### 3.2 素朴な方法とその欠陥

一番簡単なのは、比較対象のレートを**真の値として信じる**やり方である。

$$\hat\lambda_0 = \frac{C_2}{E_2}, \qquad \mu_0 = \hat\lambda_0 E_1, \qquad p = P(X \ge C_1 \mid X \sim \text{Poisson}(\mu_0))$$

**問題**: $\hat\lambda_0$ は推定値であって真の値ではない。$C_2$ が小さいと非常に不確かなのに、
それを確定した真実として扱っている。

数値で見る。ベースラインのレートはどちらも $0.001$、当月の露出は1000台月、観測5件とする。

| ベースライン | 素朴ポアソン | 条件付き二項 |
|---|---|---|
| $C_2 = 8$, $E_2 = 8000$（薄い） | p = 0.0037 | **p = 0.0101** |
| $C_2 = 800$, $E_2 = 800000$（厚い） | p = 0.0037 | p = 0.0037 |

素朴ポアソンは**どちらも同じ答えを出す**。ベースラインが8件しかなくても800件あっても、
区別しない。

これは危険である。$C_2 = 8$ のとき、真のレートが $0.001$ である保証はどこにもない。
$\pm\sqrt{8} \approx \pm 2.8$ 件の揺れがあるので、真のレートは $0.0007 \sim 0.0013$ の
どこかにある。もし真値が $0.0013$ なら、5件の観測は全く異常ではない。

**薄いベースラインで素朴な検定を使うと、推定誤差の分だけ誤報が増える。**
監視単位が3000もあれば、この誤報は無視できない量になる。

### 3.3 求められる性質

したがって欲しいのは、

- ベースラインが薄いときは**自動的に判定が甘くなる**
- ベースラインが厚いときは素朴な方法に近づく
- 未知の $\lambda$ を推定して代入する、という手続きを踏まない

これを満たすのが次節の条件付き二項検定である。

## 4. 条件付き二項検定 — 中核の道具

### 4.1 発想

$\lambda$ が未知であることが問題の根源だった。ならば、**$\lambda$ が式から消えるように
問題を立て直せばよい。**

その鍵が「合計で条件づける」という操作である。

### 4.2 導出

$X \sim \text{Poisson}(\mu_1)$、$Y \sim \text{Poisson}(\mu_2)$ が独立とする。ここで

$$\mu_1 = \lambda_1 E_1, \qquad \mu_2 = \lambda_2 E_2$$

**「合計が $n$ だった」という条件のもとでの $X$ の分布**を求める。

$$P(X = x \mid X+Y = n) = \frac{P(X=x,\; Y=n-x)}{P(X+Y=n)} = \frac{P(X=x)\,P(Y=n-x)}{P(X+Y=n)}$$

分子は独立性より積になる。分母は性質(P2)より $\text{Poisson}(\mu_1+\mu_2)$。

$$= \frac{\dfrac{\mu_1^x e^{-\mu_1}}{x!} \cdot \dfrac{\mu_2^{n-x} e^{-\mu_2}}{(n-x)!}}{\dfrac{(\mu_1+\mu_2)^n e^{-(\mu_1+\mu_2)}}{n!}}$$

指数部分は $e^{-\mu_1}e^{-\mu_2} = e^{-(\mu_1+\mu_2)}$ で**完全に相殺する**。

$$= \frac{n!}{x!\,(n-x)!} \cdot \frac{\mu_1^x \mu_2^{n-x}}{(\mu_1+\mu_2)^n} = \binom{n}{x} \left(\frac{\mu_1}{\mu_1+\mu_2}\right)^x \left(\frac{\mu_2}{\mu_1+\mu_2}\right)^{n-x}$$

これは二項分布そのものである。

$$X \mid (X+Y=n) \;\sim\; \text{Binomial}\!\left(n,\; \pi\right), \qquad \pi = \frac{\mu_1}{\mu_1 + \mu_2}$$

### 4.3 帰無仮説を代入する — ここが核心

$H_0: \lambda_1 = \lambda_2 = \lambda$ を仮定する。すると

$$\pi = \frac{\lambda_1 E_1}{\lambda_1 E_1 + \lambda_2 E_2} = \frac{\lambda E_1}{\lambda E_1 + \lambda E_2} = \frac{E_1}{E_1 + E_2}$$

**$\lambda$ が約分されて消えた。**

これが決定的である。帰無仮説のもとでの $X$ の分布は、**未知のレートに一切依存せず、
既知の露出だけで決まる**。推定も代入も不要になった。

### 4.4 p値

観測値 $C_1$ 以上が出る確率（上側裾）を計算する。

$$p\text{-value} = P(X \ge C_1) = \sum_{i=C_1}^{n} \binom{n}{i} \pi^i (1-\pi)^{n-i}, \qquad n = C_1 + C_2, \quad \pi = \frac{E_1}{E_1+E_2}$$

これが `cusum_monitor.binom_sf(x, n, p)` の中身。信号B・信号Cはどちらもこの1本の式を使う。

### 4.5 直感的な言い換え

$n = C_1 + C_2$ 件の交換が起きた。$H_0$ が正しければ、各件が対象側で起きたか比較側で
起きたかは、**露出の比だけで決まるコイン投げ**のはずである。

露出が半々（$E_1 = E_2$）なら $\pi = 0.5$ の公正なコイン。100件のうち70件が対象側に
偏っていたら、それは偶然か？ という問いに帰着する。

**未知のレートを推定するのではなく、「起きた件数をどう振り分けるか」という問題に
変換した**のが、この検定の巧みなところである。

### 4.6 なぜ薄いベースラインで保守的になるのか

$C_2$ が小さいと $n = C_1 + C_2$ も小さい。**試行回数の少ない二項分布は裾が厚い。**

コイン投げで考えると分かりやすい。

- 10回投げて7回表 → 珍しくない（$p \approx 0.17$）
- 1000回投げて700回表 → 天文学的に珍しい（$p < 10^{-30}$）

同じ「7割」でも、試行回数によって驚きの度合いが全く違う。条件付き二項はこの構造を
自動的に織り込む。**ベースラインの薄さが、そのまま判定の甘さになる。**
追加の補正項も、事前分布の指定も要らない。

§3.2 の数値（薄いとき 0.0037 → 0.0101、厚いとき 0.0037 → 0.0037）は、まさにこの効果である。

## 5. 閾値検出：累積使用率の絶対水準

3つの検出器のうち、これだけが**検定を使わない**。累積の比率を基準値と比べるだけ。
確実だが遅い、という性格がここから来る。

### 5.1 定義

$$\text{累積使用率}(T) = 100 \times \frac{\sum_{t \le T} C_t}{F_T} \;[\%]$$

分子は交換件数の累積、分母は**当月時点の**累積販売台数。これが基準値 $X$（既定5%）を
超えたら発火する。

$$\text{発火} \iff \text{累積使用率}(T) \ge X$$

部品ごとに $X$ を変えられる（`THRESHOLD_OVERRIDES`）。探索は
$(\text{biz},\text{dev},\text{part}) \to (\text{biz},\text{dev}) \to (\text{biz})$
の順で、最初に見つかったものを使う。

### 5.2 §2 のレートとの関係

§2 の $\lambda = C/E$（$E$ は台数×月）とは**分母が違う**ことに注意。

| | 分子 | 分母 | 単位 |
|---|---|---|---|
| レート $\lambda$ | 月次件数 | 台数×月 | 1台1ヶ月あたり |
| 累積使用率 | 累積件数 | 当月の台数 | 1台あたり（生涯） |

累積使用率は「出荷した1台あたり、これまでに何個その部品を交換したか」。
$X = 5\%$ なら「100台に5個」。直感的で、現場の会話にそのまま乗る量である。

レート $\lambda$ が一定なら、累積使用率はおおよそ

$$\text{累積使用率}(T) \approx 100\lambda \cdot \frac{\sum_{t\le T} F_t}{F_T}$$

と書ける。$F$ が一定なら $100\lambda T$ で**時間に比例して育つ**。

### 5.3 なぜ遅いのか

上の式から、閾値に到達するまでの月数が計算できる。$\lambda = 0.001$（月0.1%）として:

| 基準 $X$ | 台数横ばい | 台数が毎月130台増 |
|---|---|---|
| 2% | 20ヶ月 | 29ヶ月 |
| 5% | 50ヶ月 | **84ヶ月** |

**台数が伸びている間は分母も育つので、さらに遅れる。** 5%基準だと7年かかる計算になる。

これは欠陥ではなく役割分担である。累積使用率は**取り返しのつかない水準に達したことを
確実に検知する**量であって、早期警報ではない。早さは信号B（横断比較）と
信号C（単月急増）が担当する。

### 5.4 構造的にスパイクを検知できない

分母 $F_T$ が積み上がるため、単月の急増はほとんど動かさない。

3000台に対して月10件が突然30件になっても、累積使用率の増分は

$$\frac{30 - 10}{3000} = 0.67\%$$

にすぎない。すでに累積が3%あるなら 3.67% で、5%基準には届かない。
**信号Cが必要な理由がここにある。**

### 5.5 系列の扱い

`series_rates` は2種類の系列を作る。

- **合算系列**（`COMBINED`）… 全販社を合計。本線の判定はこちら
- **販社別系列**… 販社ごと。`min_denominator` 以上の台数がある販社のみ

統合インボックスでは、両系列のうち**最も高い累積率**を採用している
（`g.loc[g["rate_pct"].idxmax()]`）。どの系列で超えたかは `対象販社` 列に出る。

### 5.6 注目度

$$\text{注目度}_{\text{閾値}} = \min\left(\frac{\text{観測率}}{X},\; 3.0\right)$$

基準の何倍かをそのまま使う。2倍なら2.0、3倍以上は3.0で頭打ち。

## 6. 信号B：機種間ピア比較

### 6.1 何を解決するのか

CUSUM は**自己参照型**である。その部品自身の過去と比較して変化を検出する。したがって

> 最初から高い水準で、平坦に推移している部品

は原理的に検知できない。変化していないのだから。ところが過去に人が見つけていた不具合は、
まさにここに集中していた。

**時間方向に変化がないなら、空間方向（他機種）と比べればよい。** これが信号Bの発想である。

### 6.2 比較の単位

同じ SF-CODE（部品の種類）を持つ他機種をピアとする。

- 対象：機種 $X$ の $(C_{\text{focal}},\, E_{\text{focal}})$
- ピア：同一 $(\text{biz},\, \text{SF})$ の**他機種をプールした** $(C_{\text{peer}},\, E_{\text{peer}})$

プールしてよい根拠は性質(P2)。独立なポアソンの和はポアソンなので、5機種を合算しても
検定の枠組みは変わらない。

$$n = C_{\text{focal}} + C_{\text{peer}}, \qquad \pi = \frac{E_{\text{focal}}}{E_{\text{focal}} + E_{\text{peer}}}, \qquad p = P(X \ge C_{\text{focal}})$$

**部番を合算して SF 単位で見る**ので、機種ごとに部番が違っても比較できる。
部品対応表が不要になるのはこのため。

### 6.3 効果量 O/E

p値とは別に、**どれくらい高いか**を測る量を定義する。

$$\hat\lambda_{\text{peer}} = \frac{C_{\text{peer}}}{E_{\text{peer}}}, \qquad \text{Expected} = \hat\lambda_{\text{peer}} \cdot E_{\text{focal}}$$

$$\text{O/E} = \frac{C_{\text{focal}}}{\text{Expected}}$$

「ピアと同じレートだったら何件のはずか」に対する実測の倍率。O/E = 2.5 なら**ピアの2.5倍**。

p値が「偶然か否か」を測るのに対し、O/E は「実務的にどれだけ大きいか」を測る。
§7 で見るように、**運用上はこちらが主役になる。**

### 6.4 交絡因子1：経過月

発売から半年の機種と5年目の機種を、生の累積レートで比べてはいけない。
初期不良期は故障率が高いのが正常だからである。

対処は単純で、**経過月 $0 \sim T_{\text{cap}}$ の区間だけを切って比較する**
（`elapsed_cap`、既定36）。

$$C = \sum_{e=0}^{T_{\text{cap}}} C_e, \qquad E = \sum_{e=0}^{T_{\text{cap}}} F_e$$

全機種を同じ区間で揃えれば、初期不良カーブの形が共通である限り相殺される。
窓を完走していない機種（発売から36ヶ月経っていない）は `require_full=True` で除外する。

### 6.5 交絡因子2：部番数（nb）

同じ SF-CODE に部番が2つある機種は、1回の修理で2点使う設計かもしれない。
すると件数が構造的に膨らむ。

**この膨張は時間で一定なので CUSUM には無害だが、横断比較では致命的である。**
膨張率の差がそのまま「異常」に見える。

実データで測った結果（nb=1 の機種を基準にした交換率の比）:

| nb | 比 | 比 ÷ nb |
|---|---|---|
| 2 | 1.39 | 0.69 |
| 3 | 3.66 | 1.22 |
| 4 | 5.09 | 1.27 |

**nb で割る正規化は成立しない。** 残差が 0.69 / 1.22 / 1.27 とバラバラで、
どの係数でも揃わない。特に nb=2 を2で割ると 0.69 倍、つまり本来より3割低く見え、
**真の異常を沈黙させる**方向に誤る。

さらに nb=3 が 3.66、nb=4 が 5.09 と**期待値（3, 4）を超えている**。
解釈は因果の逆流である。

> 交換が多い部品 → 設計変更・改良品番の追加 → 部番数が増える

**nb は設計属性であると同時に、不具合の結果でもある。**
nb で正規化する行為は、異常の証拠を割り算で消すことになる。

したがって採用した対処は **nb 層別**：`nb` が一致する機種同士だけを比較する。
膨張率が共通なら、比の中で相殺される。

$$\text{比較群} = \{(\text{biz},\, \text{SF},\, \text{nb}) \text{ が一致する機種}\}$$

代償として、nb がばらつく群ではピアが足りなくなり判定対象から外れる（実データで約半数）。
これは**構造的な穴**として受け入れ、閾値検出器に任せる。

### 6.6 交絡因子3：ピアプールの汚染

同じ群に異常機種が2つあると、互いに相手を「高いピア」として見るため、
基準が押し上げられて**両方とも正常に見える**。

対処は2パス方式。

1. **1パス目**：全機種でピア比較 → 発火した機種を記録
2. **2パス目**：発火機種をピアプールから除外して再計算

合成データでの検証では、正常機種の O/E が $0.73 \to 1.05$ に是正された
（0.73 という値自体が、基準が押し上げられていた証拠）。

副次的な効果として、**「新常態受容」で既知の高水準と認めた機種は自動的にピアプールから
外れる**。人間の判断が統計に反映される経路になっている。

## 7. 信号C：時間軸のローリング比較

### 7.1 何を解決するのか

閾値検出器は累積使用率を見る。

$$\text{累積率} = \frac{\sum_{t \le T} C_t}{F_T}$$

分母が積み上がっていくため、**単月の急増ではほとんど動かない**。
3000台に対して10件が30件に増えても、累積率は 0.3% → 0.9% 程度の変化にしかならず、
閾値には届かない。

構造的にスパイクを検知できない。ここを埋めるのが信号Cである。

### 7.2 比較の単位

**機種 × 部番 × 販社**（合算しない）。1国だけ3倍になっても、他4国が平常なら
合算では埋もれるため。

ベースラインは**直近 $L$ ヶ月のローリング窓**（既定12）。

- 対象：当月 $T$ の $(C_T,\, F_T)$
- ベースライン：$\left(\sum_{t=T-L}^{T-1} C_t,\;\; \sum_{t=T-L}^{T-1} F_t\right)$

検定式は §4.4 と全く同じ。

$$n = C_T + C_{\text{base}}, \qquad \pi = \frac{F_T}{F_T + E_{\text{base}}}, \qquad p = P(X \ge C_T)$$

**信号Bとの違いは「何をピアとするか」だけ**である。信号Bは他機種、信号Cは自分の過去。
数式は共通。

### 7.3 露出の左側打ち切り

販社別のデータには構造的な癖がある。

> 修理が1件でも入る前の月は、行が生成されない

したがって販社別の $F_t$ は、その販社で初回修理が起きて以降しか存在しない。
ベースラインが不当に短くなる。

ガードを2つ置いている。

- `min_base_months`（既定6）：ベースラインに最低6ヶ月ないと判定しない
- `min_base_count`（既定3.0）：ベースライン窓の件数が3未満なら判定しない

これは検定の保守性とは別の、**データ品質のためのガード**である。

### 7.4 既知の性質：緩やかな上昇での誤発火

ローリングベースラインは**上昇トレンドに遅れて追随する**。したがって緩やかに増加して
いる系列では、上振れした月が相対的に大きく見えて発火しやすい。

合成テストで再現済み（判定500行で2件 ＝ $\alpha = 0.005$ の設計値どおり）。

これはバグではない。**緩やかな上昇は閾値・CUSUM の担当領域**であり、
信号Cの守備範囲外である。運用では「単月か継続か」を目視で切り分ければ足りる。

### 7.5 検定回数の問題

3086単位 × 5販社 ≈ **15,000系列**を毎月検定する。$\alpha = 0.005$ なら、
帰無仮説がすべて正しくても

$$15000 \times 0.005 = 75 \text{ 件/月}$$

の誤報が期待される。これが `tune_c_alpha.py` で $\alpha$ を実測して絞る理由である。

**信号Bとは事情が違う**ことに注意。信号Bは機種×SF単位で数百、しかも発火すると
12ヶ月抑制されるので、検定回数の問題は相対的に小さい。

### 7.6 ゼロベースラインの扱い

最も拾いたいパターンは「**毎月ほぼ0件の部品が、突然まとまって入庫する**」である。
ところが素直に実装すると、これが構造的に検知できない。

$$C_{\text{base}} = 0 \;\Rightarrow\; \hat\lambda = 0 \;\Rightarrow\; \mu = 0 \;\Rightarrow\; \text{O/E が定義できない}$$

条件付き二項の方は $C_{\text{base}} = 0$ でも問題なく定義できる。
$n = C_T + 0 = C_T$ なので

$$p = P(X \ge C_T \mid X \sim \text{Binomial}(C_T, \pi)) = \pi^{C_T}$$

「全部が当月に落ちる確率」そのもの。$\pi = 1/13$、$C_T = 5$ なら
$p = (1/13)^5 = 2.7\times10^{-6}$ で、正しく有意になる（数値でも一致を確認済み）。

**詰まるのは O/E の分母だけ**なので、そこにだけ下駄を履かせる。

$$\mu_{\text{eff}} = \frac{\max(C_{\text{base}},\, 0.5)}{E_{\text{base}}} \cdot F_T$$

「0.5件はあったかもしれない」とみなす（Jeffreys 事前分布に相当する発想）。
**p値の計算には実測の $C_{\text{base}}$ をそのまま使う**ので、検定の厳密さは損なわれない。

あわせて `min_base_count` の既定を **0**（制限なし）にした。条件付き二項は
ベースラインが薄いほど自動で保守側に開く（§4.6）ので、件数で足切りする必要が
そもそもない。3 のままだと最も拾いたいパターンを判定前に消してしまう。

### 7.7 もともと振れの大きい系列への対処

`min_oe` は純粋なランダム変動を完全に止める。月10件以上の系列では、
異常がなければ発火率は0%だった（シミュレーション400回×48ヶ月）。

| 月平均 | min_oe なし | min_oe = 3.0 |
|---|---|---|
| 10件 | 0.37% | **0.00%** |
| 30件 | 0.44% | **0.00%** |
| 100件 | 0.48% | **0.00%** |

したがってそれでも鳴る系列は、**本当に3倍以上振れている**。原因はポアソン誤差ではなく、
まとめ発注・季節性・報告の遅延まとめ計上といった構造的なもので、倍率の下限では止まらない。

対処として**自己履歴による下限**（`exceed_hist`）を用意した。ベースライン窓の中で
その系列が見せた最大の振れ幅を基準にする。

$$\text{hist\_floor} = \max_{i \in \text{窓}}\left(\frac{C_i / F_i}{C_{\text{base}} / E_{\text{base}}}\right) \times \text{exceed\_hist}$$

発火条件の倍率下限を $\max(\text{min\_oe},\; \text{hist\_floor})$ にする。
もともと出入りが大きい系列は自動的に鈍感になり、振れの小さい通常部品には影響しない。

| exceed_hist | 平常時の発火 | 本物(8倍)の検知 |
|---|---|---|
| 0.0（無効） | 7.40% | 98.8% |
| 1.0 | 6.14% | 95.2% |
| **1.2** | **4.74%** | **84.5%** |
| 1.5 | 3.08% | 57.0% |

> **試して却下した案**: 過分散補正（分散が大きい系列ほどp値を保守側に補正する、
> 統計的には筋の良い方法）も実装して測ったが、**本物の検知率が 98.8% → 17%** と
> 壊滅した。件数の少ない月で正規近似が効きすぎるのが原因。採用していない。

消耗品など性質上つねに出入りが多いと分かっている部品は、統計に頼らず
`C_EXCLUDE` で名指しで外す方が確実である。

## 8. p値と効果量 — なぜ効果量が主レバーなのか

### 8.1 p値は件数に強く依存する

同じ効果量（O/E = 1.3）で、件数だけを変えて p値を計算する。

| $C_{\text{focal}}$ | $C_{\text{peer}}$ | p値 |
|---|---|---|
| 10 | 7 | 0.31 |
| 30 | 23 | 0.21 |
| 100 | 76 | 0.041 |
| 300 | 230 | 0.0013 |
| 1000 | 769 | $2.2 \times 10^{-8}$ |

**効果量は全く同じ**なのに、p値は 0.31 から $10^{-8}$ まで7桁動く。

これは検定として正しい振る舞いである（サンプルが増えれば小さな差も確実に検出できる）。
しかし**運用上は困る**。O/E = 1.3 は実務的には「誤差の範囲」であって、
部品を調査する理由にならないからだ。

### 8.2 逆に、件数を固定して効果量を変えると

$C_{\text{focal}} = 500$ で固定。

| O/E | p値 |
|---|---|
| 1.1 | 0.073 |
| 1.3 | $5.4 \times 10^{-5}$ |
| 2.0 | $2.2 \times 10^{-20}$ |
| 3.0 | $4.5 \times 10^{-40}$ |

O/E が 1.3 から 2.0 に変わるだけで、p値は**15桁**動く。

$\alpha$ をこの範囲のどこに置いても、実質的に同じ結果になる。実データのスイープでも、
$\alpha$ を 0.05 から 0.001 へ**50倍絞っても発火件数が1件も変わらなかった**。

### 8.3 なぜこうなるのか

二項分布の裾は、$n$ が大きいと指数関数的に減衰する。大偏差原理により、おおよそ

$$-\log p \;\approx\; n \cdot D(\hat\pi \,\|\, \pi)$$

ここで $D$ は KL ダイバージェンス（2つの確率の「隔たり」）。

$$D(\hat\pi\|\pi) = \hat\pi\log\frac{\hat\pi}{\pi} + (1-\hat\pi)\log\frac{1-\hat\pi}{1-\pi}$$

重要なのは、**$-\log p$ が $n$ に比例して増える**という点である。$n$ が数百なら
$-\log p$ は数十〜数百のオーダーになり、p値は $10^{-50}$ のような値を平気で取る。

**p値は「差があるか」を測る量であって、「差が大きいか」を測る量ではない。**
件数が多ければ、どんな小さな差でも「差がある」と正しく答える。

### 8.4 過分散という追加の問題

さらに実データでは、帰無仮説 $H_0: \lambda_1 = \lambda_2$ **がそもそも成り立っていない**。

機種は正当な理由で違うレートを持つ。

- 設計世代の違い
- 市場構成（業務用比率、地域）
- 使用環境（温度、稼働時間）

つまり真のレート自体が機種ごとにばらついている。これを**過分散**（overdispersion）と呼ぶ。

過分散があると、ポアソン仮定より実際のばらつきが大きいので、**p値は本来より小さく出る**。
統計的に有意な発火が実務的に無意味な例で埋まる原因になる。

### 8.5 結論：効果量で切る

したがって発火条件は

**信号B**

$$\text{O/E} \ge \text{min\_oe} \;\wedge\; p \le \alpha \;\wedge\; C_{\text{focal}} \ge \text{min\_count} \;\wedge\; C_{\text{peer}} \ge \text{min\_peer\_count}$$

**信号C**

$$\text{O/E} \ge \max(\text{min\_oe},\, \text{hist\_floor}) \;\wedge\; p \le \alpha \;\wedge\; C_T \ge \text{min\_count} \;\wedge\; (C_T - \mu_{\text{eff}}) \ge \text{min\_excess}$$

- **`min_oe` が主レバー**。実務的な意味を直接指定する
- **$\alpha$ は補助**。件数の少ない群で偶然 O/E が跳ねるのを防ぐガード
- **件数の下限**（§9）は、薄い単位がノイズで上位を占めるのを防ぐ

注目度（並び順）も O/E ベースにしてある。旧実装は $\log p / \log \alpha$ だったが、
p値が $10^{-58}$ と $10^{-169}$ のような値を取る以上、順位の物差しにならない。

$$\text{注目度} = \min\left(1 + 2\cdot\frac{\text{O/E} - \text{min\_oe}}{2\,\text{min\_oe}},\;\; 3.0\right)$$

`min_oe` で1.0、その3倍で3.0 になる線形スケール。

> **統計的有意性と実務的重要性は別物である。**
> これは信号B/Cに限らず、大規模な監視システム一般に当てはまる教訓。

## 9. 件数の薄さがもたらす問題

§4.6 で見たとおり、条件付き二項は件数が薄いと**保守的に**なる。つまり誤って発火する
確率は上がらない。それなら件数の下限は要らないはずだが、実際には要る。理由は
**発火率ではなく O/E の大きさ**にある。

### 9.1 薄い単位は O/E が跳ねる

全機種が同じ真のレートを持つ（＝異常なし）状況で、件数規模だけを変えて
シミュレーションした結果。

| 1機種あたり平均件数 | 誤発火率 | 平均 O/E | **ノイズだけで出る O/E 最大** |
|---|---|---|---|
| 3件 | 0.20% | 1.10 | **6.67** |
| 10件 | 0.30% | 1.03 | **2.91** |
| 50件 | 0.05% | 1.01 | 1.51 |
| 200件 | 0.00% | 1.00 | 1.35 |

**誤発火率自体はどの規模でも低い。** 問題は右端の列である。

理由は §1.3 の変動係数にある。ポアソンの標準偏差は $\sqrt{\mu}$ なので、
相対的なばらつきは

$$\frac{\sigma}{\mu} = \frac{1}{\sqrt{\mu}}$$

$\mu = 3$ なら 58%、$\mu = 200$ なら 7%。**薄い単位では O/E が構造的に大きく振れる。**

### 9.2 なぜそれが困るのか

注目度が O/E ベースだから（§8.5）。

> 10件の部品がノイズで出した O/E = 2.9 が、
> 500件の部品の真の O/E = 2.5 より**上位に来る**

上位N件しかレビューしない運用では、薄い単位が枠を占拠して本物が押し下げられる。
**検知の問題ではなく、順位の問題である。**

### 9.3 対処：両側に件数の下限を置く

信号Bでは、対象機種とピアプールの**両方**に下限を置く。ピア側が薄いと期待値の推定が
不安定になり、同じく O/E が暴れるため。

$$C_{\text{focal}} \ge \text{min\_count} \quad\wedge\quad C_{\text{peer}} \ge \text{min\_peer\_count}$$

下限を振ってノイズ由来の O/E 上限を測った結果:

| 下限 | 判定対象率 | ノイズ由来の O/E 最大 |
|---|---|---|
| 3（旧既定） | 89.8% | **5.33** |
| 10 | 59.9% | 4.36 |
| **20** | 44.3% | **2.05** |
| 50 | 23.8% | 1.51 |

20 でノイズの到達範囲が 2 程度に収まる。`min_oe = 1.5` と組み合わせれば、
ノイズと本物の境界がかろうじて分離する水準になる。

**代償として判定対象が半減する。** 累積件数の少ない部品の異常は信号Bでは拾えなくなるが、
そもそも信号Bは「水準が高い部品」を探す検出器であり、薄い部品の突発は信号Cの担当領域
である。役割分担としては整合している。

## 10. 実装上の数値的注意

### 10.1 二項係数を直接計算してはいけない

$$\binom{1000}{500} \approx 2.7 \times 10^{299}$$

倍精度浮動小数点の上限（$\approx 1.8 \times 10^{308}$）に迫る。
$n$ が数千になれば確実にオーバーフローする。

対処は**対数を取ってから指数に戻す**こと。

$$\log\!\left[\binom{n}{i}\pi^i(1-\pi)^{n-i}\right] = \log\Gamma(n{+}1) - \log\Gamma(i{+}1) - \log\Gamma(n{-}i{+}1) + i\log\pi + (n{-}i)\log(1{-}\pi)$$

ここで $\log\Gamma$ は対数ガンマ関数で、$\log(n!) = \log\Gamma(n+1)$。Python では `math.lgamma`。

実装（`cusum_monitor.binom_sf`）:

```python
log_pmf = (lgamma(n+1) - lgamma(i+1) - lgamma(n-i+1)
           + i*log(p) + (n-i)*log1p(-p))
total += exp(log_pmf)
```

各項は個別に $\exp$ してから足す。個々の確率は必ず $[0,1]$ に収まるのでオーバーフローしない。

### 10.2 log1p を使う理由

$\log(1-\pi)$ を素直に書くと、$\pi$ が非常に小さいとき精度が落ちる。
$1 - 10^{-16}$ は倍精度では $1.0$ と区別できない。

`math.log1p(-p)` は $\log(1+x)$ を $x$ が小さいときも正確に計算する専用関数。
信号Cでは $\pi = F_T/(F_T + E_{\text{base}})$ が $1/13$ 程度になるので、実際に効いてくる。

### 10.3 大きな n での正規近似

$n$ が2万を超えると、和の項数が多くなり計算時間が問題になる。
この領域では中心極限定理による正規近似で十分。

$$Z = \frac{C_1 - 0.5 - n\pi}{\sqrt{n\pi(1-\pi)}}, \qquad p \approx \frac{1}{2}\,\text{erfc}\!\left(\frac{Z}{\sqrt2}\right)$$

$-0.5$ は**連続性補正**。離散分布を連続分布で近似するとき、$P(X \ge x)$ を
$P(X > x - 0.5)$ とみなす補正である。これがないと系統的にp値が小さく出る。

`erfc`（相補誤差関数）は `math` にあるので scipy 不要。

### 10.4 計算量の削減

信号Cは15,000系列 × 24ヶ月 = 36万回の判定になる。全部に正確検定をかけると重い。

事前フィルタで枝刈りする。

```python
if use[t] < min_count or use[t] <= expected:
    continue     # 発火しえないので p は計算しない
```

観測値が期待値以下なら $p > 0.5$ で絶対に発火しない。件数が `min_count` 未満でも同様。
実測で36万 → 3000回程度（1%以下）まで減る。

### 10.5 O/E の分母がゼロになる場合

$E_{\text{peer}} = 0$（ピアが存在しない）や $\hat\lambda_{\text{peer}} = 0$
（ピアで1件も起きていない）のとき、O/E は定義できない。

このとき**発火させない**のが正しい。「ピアが0件なのに対象が5件」は一見異常だが、
ピア側の露出が薄いだけかもしれず、条件付き二項でも $n = 5$ の小標本になって
有意にならない。無理に判定せず沈黙させる。

`min_peers`（既定2）でピア機種数を、`min_base_count` でベースライン件数を、
それぞれ下から抑えている。

### 統合

| 設定 | 既定 | 意味 |
|---|---|---|
| `TOP_N` | 15 | 毎月レビューする件数 |
| `MULTI_BONUS` | 0.5 | 検出器が1つ増えるごとの加点 |
| `SUPPRESS_MONTHS` | 閾値6/信号B12/信号C3 | 再評価年月が空欄のときの既定抑制 |

統合注目度は

$$\text{統合注目度} = \max_d(\text{注目度}_d) + \text{MULTI\_BONUS}\times(\text{検出器数}-1)$$

複数検出器の同時発火は真陽性率が高いはずなので加点する。

## まとめ

1. **月次件数はポアソン分布**に従う。$N$ が大きく $q$ が小さいという我々の状況で
   二項分布から導かれる。
2. **露出（台数×月）で割ってレートにする**と比較可能になる。
   部番方向に露出を二重計上しないこと。
3. **閾値検出だけが検定を使わない。** 累積使用率が基準を超えたかだけを見る。
   確実だが遅く（5%基準なら50〜84ヶ月）、構造的にスパイクを検知できない。
4. **条件付き二項検定**が信号B/Cの中核。合計件数で条件づけると未知のレートが
   約分で消え、露出だけで検定できる。ベースラインが薄いほど自動的に保守側に開く。
5. **信号Bは他機種をピアに、信号Cは自分の過去をピアに**とる。数式は同一。
6. **運用の主レバーは効果量 O/E**。p値は件数に強く依存し、過分散もあって、
   実務的な大きさを測る量ではない。
7. **件数の下限が別途要る。** 誤発火率のためではなく、薄い単位がノイズで大きな O/E を
   出して上位を占拠するのを防ぐため。検知の問題ではなく順位の問題。

### 3つの検出器の関係

| | 見るもの | 早さ | 苦手なもの |
|---|---|---|---|
| **閾値** | 累積水準の絶対値 | 遅い | 単月急増、他機種との相対 |
| **信号B** | 同SF群ピアとの相対 | 中 | 群が汚染されている場合、薄い部品 |
| **信号C** | 自分の過去との相対 | 速い | 緩やかな上昇、もともと振れの大きい系列 |

**横断比較（B）と時系列比較（C・CUSUM）は補完関係にあり、片方だけでは穴が残る。**
同SF群の全機種で同じ部品が不良なら B は沈黙し、最初から高い水準で平坦なら C も沈黙する。
