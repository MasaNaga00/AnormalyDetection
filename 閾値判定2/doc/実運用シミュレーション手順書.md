## 2. レビュー — 1件ずつ判断する

`出力/202412/レビュー用_202412.csv` を Excel で開く。判断に使う列:

| 列 | 見方 |
|---|---|
| **検出器** | どの信号で鳴ったか。複数なら確度が高い |
| **統合注目度** | 並び順の根拠。各検出器の最大スコア＋検出器1つにつき0.5加点 |
| **指標** | 検出器ごとの根拠（累積率／O/E比／p値） |
| **対象販社** | 信号Cならどの販社か |

### 検出器ごとの読み方

**閾値**が鳴った → 累積使用率が基準Xを超えた。**確実だが遅い**。
既に相当数が出た後なので、対策済みか確認する。

**信号B**が鳴った → 同じSF-CODEの他機種と比べて高い。**閾値より早い**。
指標の **O/E がピアの何倍か**を示す（O/E=2.5 ならピアの2.5倍）。
`出力/YYYYMM/信号B詳細_YYYYMM.csv` で `peer_rate`（ピアの平均レート）と
`n_peers`（比較機種数）を確認する。ピアが2〜3機種しかない群は偶然の可能性を疑う。

> **p値は見なくてよい。** 件数が数百あると桁が飛ぶ（O/E=1.27でp=6e-4、
> O/E=2.48でp=1e-58）ので、大小の判断材料にならない。**倍率で読む。**

**信号C**が鳴った → 特定販社で単月急増。`出力/YYYYMM/信号C詳細_YYYYMM.csv` で
その販社の前後数ヶ月を見て、単発か継続の入口かを切り分ける。
一括交換・在庫調整・報告の遅延まとめ計上なども単月急増として出る。

### 判断できないとき

**「保留」を選ぶ。** 翌月以降も毎月インボックスに出続けるので、忘れない。
これは「黙らせる」のではなく「見え続けさせる」ための区分。

## 3. 台帳に記入する

`出力/YYYYMM/レビュー用_YYYYMM.csv` の行をそのまま台帳（`台帳_空.xlsx` の「台帳」シート）に
貼り付け、以下の列を埋める。

### 必ず埋める

- **処置区分** … 下の8択から
- **記録日** … 記入した日
- **確認者** … 自分の名前

### 必要なときだけ埋める

- **再評価年月** … 空欄なら検出器ごとの既定期間が自動で効く（下表）
- **上書き閾値** … 「新常態受容」のときの新しい基準X（%）
- **原因メモ** … 後から見て分かるように

### 処置区分の8択

| 処置区分 | 意味 | 次に鳴るのは |
|---|---|---|
| **対策中** | 対策を実施中 | 再評価年月に再点灯 |
| **新常態受容** | この水準が正常と認める | 上書き閾値を超えたら |
| **ノイズ** | 異常ではない | 既定期間後 |
| **感度上書き** | この単位だけ感度を変える | （CUSUM用） |
| **スパイク確認** | 単月の急増を確認済み | 既定期間後 |
| **保留** | 判断保留 | **毎月出続ける** |
| **監視終了** | この部品はもう見ない | 二度と出ない |
| **機種終了** | 機種ごと終了（部番="機種全体"） | 二度と出ない |

### 再評価年月を空欄にしたときの既定抑制期間

| 検出器 | 既定 | 理由 |
|---|---|---|
| 閾値 | 6ヶ月 | 累積率は下がらないので、本来は上書き閾値で対応する |
| **信号B** | **12ヶ月** | 経過月0〜36の累積O/Eは月次でほぼ動かない |
| 信号C | 3ヶ月 | 月次のローリング比較なので自然に戻る |
| CUSUM | 1ヶ月 | 台帳リセットで別途処理される |

**抑制は検出器ごとに独立している。** 信号Bを12ヶ月抑制しても、その間に
販社で急増が起きれば信号Cは出る。「監視終了」と「保留」だけが部品全体に効く。

### 記入例

すぐ試したい場合は、用意してある `台帳_記入例.xlsx` を使う。8件それぞれに
異なる処置区分を入れてあるので、抑制の効き方の違いが一度に見られる。

| 機種/部番 | 処置区分 | 再評価年月 | 意図 |
|---|---|---|---|
| M02 / 101-0 | 対策中 | 202506 | 半年後に効果確認 |
| M06 / 102-0 | 保留 | 空欄 | 毎月見続ける |
| M01 / 100-0 | スパイク確認 | 空欄 | 3ヶ月抑制 |
| M04 / 104-1 | 新常態受容 | 空欄（上書き閾値=9.0） | 基準を9%に引き上げ |
| その他4件 | ノイズ | 空欄 | 既定期間で抑制 |

### 6.2 実データ投入前に必ず測ること

#### 信号C の `C_ALPHA`

3086単位 × 5販社 ≈ **15,000系列**を毎月検定する。`0.005` のままだと**月数十件**出て、
top_n=15 の枠を単独で食い潰す。

```bash
python tune_c_alpha.py panel.csv labels.csv
```

p値の計算は1回だけ（`scan_c.csv` に保存）。以後のスイープは軽い。

```python
import pandas as pd, tune_c_alpha as t
scan = pd.read_csv("scan_c.csv", encoding="utf-8-sig")
t.step2_sweep(scan, alphas=[1e-3, 5e-4], min_counts=[3, 5])
t.step2b_monthly(scan, alpha=0.001, min_count=3)   # 月別推移
t.missed_labels(scan, "labels.csv", 0.001, 3)      # 取りこぼしを理由つきで
```

**見るのは `単位月最大`**（機種×部番に畳んだ件数の最大月）。平均が3件でも
最大20件の月があればその月は破綻する。同じ部品で複数販社が同時に鳴るので、
`月平均`（販社別の行数）より実態に近い。

#### 信号B の `B_MIN_OE`

**信号Bはalphaで調整しない。** 効果量（ピア比）で切る。

```bash
python tune_b_minoe.py panel.csv labels.csv
```

まず出力冒頭の **`O/E の分布`** を見る。

```
O/E の分布: 中央=0.97  P90=1.08  P95=1.16  最大=4.25
```

合成データはピュアなポアソンなのでP95が1.16に収まるが、**実データは機種が
正当な理由（設計世代・市場構成・使用環境）でも差が出るのでもっと広がる**。
P95が1.4なら `min_oe=1.5` で5%が鳴る計算。分布を見てから決める。

```python
import pandas as pd, tune_b_minoe as tb
s = pd.read_csv("scan_b.csv", encoding="utf-8-sig")
tb.top_list(s, min_oe=1.5, alpha=0.005)   # 実際に何が出るかを目視
```

**`top_list` の目視が一番効く。** 「これは異常」「これは機種特性」と人が判断できる
境界がO/Eのどこにあるかは、実データなら見れば分かる。統計量より信頼できる。

> **信号Bの件数は「月次」でなく「立ち上げ初回」で考える。**
> 発火すると12ヶ月抑制されるので、初回に多く出ても翌月以降は新機種が
> 窓を完走した分の細い流入だけ。初回だけ `min_oe` を高めにして上澄みから
> 着手し、落ち着いてから下げる段階運用も現実的。

#### 過去の検出例が上位15件に入るか（**本番可否の最終判定**）

```bash
python check_rank.py panel.csv labels.csv
```

```
 機種    部番   報告年月  載った月  最良順位    検出器  上位N入り月  遅れ月 判定
M02 101-0 202410 202404      1 閾値/信号B  202404    -6  ○
```

**遅れ月がマイナス = 販社報告より先に捕捉できた。** これが「販社に勝てる」実測値。

| 判定 | 意味 | 対処 |
|---|---|---|
| **○** | 上位N件に入った | — |
| **△載るが沈む** | 検知はできているが順位で負けた | **top_n引き上げ、または別枠** |
| **×未検知** | インボックスにすら載らない | 検出器のパラメータか構造的な穴 |

**△と×を混同しないこと。** △なら `TOP_N` を上げれば解決するが、×は検出器側の問題。
`最良順位` 列に必要なNが直接出ているので、分布を見て判断する。

ラベルCSVの `発生年月` は**必ず YYYYMM**。年月日で書くと月がズレて評価を誤る。

### 6.3 触らない方がよいもの

実測・検証で決めた値。変えるときは理由を確認してから。

| 項目 | 理由 |
|---|---|
| `B_NB_STRAT = True` | nb正規化が成立しない（比が1.39/3.66/5.09と比例しない）という診断結果 |
| `B_TWO_PASS = True` | ピアプール汚染で正常機種のO/Eが0.73に潰れる実測あり |
| `SUPPRESS_MONTHS["信号B"] = 12` | 累積O/Eは月次で動かない。短くすると毎月鳴り続ける |

### 6.4 CUSUM は裏で回し続ける

triage はしない。発火記録だけ残しておく。半年後に台帳と突き合わせれば
「閾値・信号B・信号Cが拾えず、CUSUMだけが拾っていた件」が見える。
台帳の `検出器` 列が、その評価の土台になる。運用コストはほぼゼロ。

**閾値運用はCUSUMの前提条件（正解ラベル）を作る作業でもある。**
半年で数十件のラベルが溜まれば、そのときの再チューニングは今より精度が出る。
