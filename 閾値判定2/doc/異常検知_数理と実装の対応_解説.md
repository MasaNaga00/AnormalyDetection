## 1. データの形と記号

### 1.1 パネル（縦長データ）

`panel_初回.csv` の1行は「ある機種のある部番が、ある販社で、ある月に何個出たか」を表す。

```
事業コード, 開発コード, 部番, 販社, SF-CODE, ランク, 年月,   経過月, 月次使用数, 累積販売台数
E1,        M01,      100-0, A,   SF-100,  A,     202101, 0,     1,        850
```

| 列 | 内部名 | 意味 |
|---|---|---|
| 月次使用数 | `use` | その月にその部品が何個交換されたか（**分子**） |
| 累積販売台数 | `fleet` | その月時点で市場に出ている台数（**分母の材料**） |
| 経過月 | `elapsed` | 発売からの月数。機種ごとに0から始まる |
| SF-CODE | `sf` | 部品の種類。機種をまたいで対応が取れる唯一のキー |

### 1.2 ALL行の扱い（最初に理解すべき落とし穴）

元データには **販社 = A〜E の個別行と、販社 = "ALL" の合計行が両方入っている**。
これを一緒に集計すると、分子も分母もちょうど2倍になる。

`run_month.main()` は最初にここで二分する。

```python
p_all  = raw[raw["販社"] == "ALL"].copy()    # 閾値・信号B が使う
p_dist = raw[raw["販社"] != "ALL"].copy()    # 信号C が使う
```

### 1.3 露出（exposure）という考え方

「10個交換された」だけでは多いのか少ないのか分からない。**どれだけの台数が、どれだけの期間
市場にあったか**で割る必要がある。この分母を**露出** $E$ と呼ぶ。

このシステムの露出はすべて次の形をしている。

$$E = \sum_{t \in \text{窓}} (\text{その月の累積販売台数}) \qquad [\text{台}\cdot\text{月}]$$

単位は「台×月」。1000台が12ヶ月市場にあれば $E = 12000$ 台・月。
これに対して**レート** $\lambda$ は「1台が1ヶ月あたり壊れる確率」で、

$$\text{期待交換数} = \lambda \times E$$

が成り立つ。この式が全検出器に共通する土台になる。

> **注意**：累積販売台数は「売れた総数」であって「今も動いている台数」ではない。
> 発売から年数が経つと退役が進み、$E$ が実態より大きくなる。この過大評価が
> CUSUM側で問題になっている（§7.3）。信号B・Cは比の形なので影響を受けにくい。

### 1.4 式 → コード対応表

| 概念 | ファイル | 関数 |
|---|---|---|
| 列名の内部名への変換 | `state_logic.py` | `_prepare_panel()` |
| 同上（`elapsed`/`sf` つき。信号Bはこちらを使う） | `state_logic_cusum.py` | `_prepare_panel()` |
| 抜けた月を使用数0で埋める | 両方 | `_fill_zero_months()` |

`cummax()` は「累積のはずの列が途中で減っている」データ不整合を潰す処理。
累積販売台数が一時的に減ると分母が縮み、レートが見かけ上跳ね上がる。

## 2. 数学の準備

ここが本資料の核。ここさえ読めば、信号Bも信号Cも同じ式の使い回しだと分かる。

### 2.1 なぜ交換件数はポアソン分布か

$N$ 台の製品があり、各台がその月に壊れる確率が $p$ とする。壊れる／壊れないは
台ごとに独立とみなせるので、その月の交換数 $X$ は二項分布に従う。

$$X \sim \mathrm{Bin}(N, p), \qquad P(X = x) = \binom{N}{x} p^x (1-p)^{N-x}$$

ここで $N$ は数千台と大きく、$p$ は $0.001$ 程度と小さい。
$Np = \mu$ を一定に保ったまま $N \to \infty,\ p \to 0$ とすると、

$$\binom{N}{x} p^x (1-p)^{N-x} \longrightarrow \frac{\mu^x e^{-\mu}}{x!}$$

これが**ポアソン分布** $\mathrm{Po}(\mu)$ である（ポアソンの少数の法則）。

$$X \sim \mathrm{Po}(\mu), \qquad E[X] = \mu, \qquad V[X] = \mu$$

**期待値と分散が等しい**のがポアソンの特徴で、これが「ばらつきの物差し」になる。
平均10件なら標準偏差は $\sqrt{10} \approx 3.2$ 件。16件出ても2σ以内なので驚かない。

本システムでは $\mu = \lambda \cdot E$ と置く。$\lambda$ が1台1ヶ月あたりの故障率、
$E$ が露出（台・月）である。

### 2.2 ポアソンの再生性

独立な $X \sim \mathrm{Po}(\mu_1)$、$Y \sim \mathrm{Po}(\mu_2)$ について

$$X + Y \sim \mathrm{Po}(\mu_1 + \mu_2)$$

（証明は畳み込みを二項定理でまとめるだけ。省略。）
「複数月を合算しても、複数販社を合算してもポアソンのまま」という、
集計の自由度を保証する重要な性質である。

### 2.3 ★ 条件付き二項検定（信号B・信号Cの心臓部）

**問題設定**：2つのグループの故障率を比べたい。

- グループ1（対象）：露出 $e_1$、観測数 $x$
- グループ2（比較先）：露出 $e_2$、観測数 $y$

素朴には「グループ2から $\lambda_2 = y/e_2$ を推定し、$\mu = \lambda_2 e_1$ として
$P(X \ge x)$ をポアソンで計算する」としたくなる。だがこれは**$\lambda_2$ の推定誤差を
無視している**。比較先の件数が少ないとき、この方法は誤報を量産する。

**解決**：合計を固定して条件付き分布を取る。

帰無仮説 $H_0$：両者のレートが等しい（共通の未知の値 $\lambda$）。このとき

$$X \sim \mathrm{Po}(\lambda e_1), \qquad Y \sim \mathrm{Po}(\lambda e_2)$$

合計 $n = x + y$ を観測値に固定したときの $X$ の条件付き分布を計算する。

$$
P(X = x \mid X+Y = n)
= \frac{P(X=x)\,P(Y=n-x)}{P(X+Y=n)}
$$

分子分母を書き下すと（$\mu_1 = \lambda e_1,\ \mu_2 = \lambda e_2$）

$$
= \frac{\dfrac{\mu_1^{x} e^{-\mu_1}}{x!} \cdot \dfrac{\mu_2^{n-x} e^{-\mu_2}}{(n-x)!}}
       {\dfrac{(\mu_1+\mu_2)^{n} e^{-(\mu_1+\mu_2)}}{n!}}
= \binom{n}{x} \left(\frac{\mu_1}{\mu_1+\mu_2}\right)^{x}
               \left(\frac{\mu_2}{\mu_1+\mu_2}\right)^{n-x}
$$

ここで $\mu_1/(\mu_1+\mu_2) = \lambda e_1 / (\lambda e_1 + \lambda e_2) = e_1/(e_1+e_2)$
となり、**未知の $\lambda$ が消える**。したがって

$$\boxed{\;X \mid (X+Y=n) \;\sim\; \mathrm{Bin}\!\left(n,\ \pi\right), \qquad \pi = \frac{e_1}{e_1 + e_2}\;}$$

**p値**（上側片側検定）は

$$p = P(X \ge x) = \sum_{i=x}^{n} \binom{n}{i} \pi^{i} (1-\pi)^{n-i}$$

**この検定の意味を言葉にすると**：
「合計 $n$ 件の故障が起きたとき、それが露出の比 $\pi$ どおりに配分されるはずだ。
実際には対象側に $x$ 件も偏った。これは偶然か？」

**なぜ素朴なポアソン検定より優れるか**：
比較先のデータが薄い（$y$ が小さい）と $n$ も小さくなり、二項分布の裾が厚くなって
p値が大きく出る＝**自動的に保守側に開く**。推定の不確かさが検定に織り込まれている。
逆に比較先が十分厚ければ、素朴なポアソン検定に一致していく。

### 2.4 O/E比と検定統計量の関係（混同しやすい点）

コードには2つの「期待値」が登場する。区別が必要。

| 名前 | 定義 | 使い道 |
|---|---|---|
| `expected` | $\hat\lambda_{\text{peer}} \cdot e_1$、ただし $\hat\lambda_{\text{peer}} = y/e_2$ | **人間が見る指標**（何倍か） |
| 検定の期待値 | $n\pi = (x+y)\cdot e_1/(e_1+e_2)$ | 検定の内部（プール推定） |

`O_E` は前者を使う。$O/E = x / \text{expected}$ で「ピアの何倍か」を表す。
一方 p値は後者に基づく。$x$ 自身が $n$ に含まれるため、$n\pi$ は `expected` より大きくなる。

> **§4.4 の実例**：M02 は $x=691$、`expected` $=162.75$ なので $O/E = 4.25$。
> 一方 $n\pi = 1993 \times 1/9 = 221.4$。数字が違って見えるが、
> **どちらも正しく、役割が違う**。表示は O/E、判定は p値。

### 2.5 有意水準 α と対数スコア

p値が小さいほど「偶然では説明しにくい」。閾値 $\alpha$ を決めて $p \le \alpha$ で発火とする。
本システムは $\alpha = 0.005$（既定）。

ただし p値そのものは $10^{-169}$ のような極端な値を取り、順位づけに使いにくい。
そこで**対数尺度**に直す。

$$\text{生スコア} = \min\left(\frac{\log p}{\log \alpha},\ 3.0\right)$$

- $p = \alpha$ のとき、ちょうど 1.0（発火の境界）
- $p = \alpha^2$ のとき 2.0（$\log$ が積を和に変えるので「αの何乗か」を測っている）
- 上限3.0でクリップ。$10^{-169}$ と $10^{-200}$ の差に意味はないため

$\log \alpha < 0$、$\log p < 0$ なので比は正になる。

### 2.6 二項の裾確率をどう計算するか（`binom_sf`）

$\binom{n}{i}$ は $n$ が大きいと桁があふれる（$\binom{2000}{700}$ は10進で500桁超）。
そこで**対数で計算してから戻す**。

$$\log\left[\binom{n}{i}\pi^i(1-\pi)^{n-i}\right]
= \log \Gamma(n{+}1) - \log \Gamma(i{+}1) - \log \Gamma(n{-}i{+}1) + i\log\pi + (n{-}i)\log(1{-}\pi)$$

ここで $\Gamma(n+1) = n!$（ガンマ関数）。標準ライブラリの `math.lgamma` が
$\log\Gamma$ を直接くれるので、階乗を作らずに済む。

```python
# cusum_monitor.binom_sf() の中核
log_pmf = (math.lgamma(n + 1) - math.lgamma(i + 1) - math.lgamma(n - i + 1)
           + i * log_p + (n - i) * log_q)
total += math.exp(log_pmf)
```

`log_q = math.log1p(-p)` は $\log(1-p)$ の高精度版。$p$ が極小のとき
$1-p$ が丸められて情報が落ちるのを防ぐ。

**この関数が scipy 禁止という制約への回答**である。`scipy.stats.binom.sf` と同じものを
標準ライブラリだけで書いている。

### 2.7 正規近似へのフォールバック（中心極限定理）

`binom_sf` は $i = x$ から $n$ まで足すループなので、$n$ が10万を超えると遅い。
$n$ が大きければ中心極限定理により

$$X \approx \mathcal{N}\big(n\pi,\ n\pi(1-\pi)\big)$$

と近似できる。離散を連続で置き換えるので**連続性補正** $-0.5$ を入れて

$$z = \frac{x - 0.5 - n\pi}{\sqrt{n\pi(1-\pi)}}, \qquad
P(X \ge x) \approx \frac{1}{2}\,\mathrm{erfc}\!\left(\frac{z}{\sqrt2}\right)$$

$\mathrm{erfc}$ は相補誤差関数で、$\frac12\mathrm{erfc}(z/\sqrt2)$ が
標準正規分布の上側確率にあたる。`math.erfc` に入っている。

```python
# signal_b_peer._cond_binom_p() の後半
if n <= max_exact:              # max_exact = 20000
    return cm.binom_sf(int(round(x)), n, p)
mu = n * p
sd = math.sqrt(n * p * (1.0 - p))
z = (x - 0.5 - mu) / sd
return 0.5 * math.erfc(z / math.sqrt(2.0))
```

## 3. 検出器1：閾値（累積使用率）

### 3.1 定義

3つの中で唯一、検定を使わない。ある月 $T$ における

$$\text{累積使用率}(T) = 100 \times \frac{\sum_{t \le T} \text{月次使用数}(t)}{\text{累積販売台数}(T)} \quad [\%]$$

これが基準 $X$（既定 5.0%）を超えたら発火。

```python
# state_logic.series_rates()
out["rate_pct"] = np.where(out["cum_sales"] > 0,
                           100.0 * out["cum_use"] / out["cum_sales"], np.nan)
```

分子の `cum_use` は `_prepare_panel()` の中で作られる。

```python
df["cum_use"] = df.groupby(["biz","dev","part","dist"])["monthly_use"].cumsum()
```

### 3.2 実測例

`panel_初回.csv`、判定月 202412、閾値 5.0% での上位。

| 機種 | 部番 | 累積使用数 | 累積販売台数 | 累積率 |
|---|---|---|---|---|
| M02 | 101-0 | 969 | 8350 | **11.60%** |
| M04 | 104-1 | 689 | 7960 | 8.66% |
| M06 | 102-0 | 577 | 7700 | 7.49% |

M02/101-0 は $969/8350 = 11.60\%$ で閾値5%を大きく超える。

### 3.3 なぜスパイクを検知できないか（重要な構造）

累積率の分子・分母はどちらも単調増加する。月 $T$ から $T+1$ への変化を見ると、

$$
\text{rate}(T{+}1) - \text{rate}(T)
= 100\left(\frac{U_T + u_{T+1}}{F_{T+1}} - \frac{U_T}{F_T}\right)
$$

$F$（累積販売台数）が十分大きく育っていると、単月の $u_{T+1}$ が3倍になっても
分子全体 $U_T + u_{T+1}$ の変化率は小さい。**分母の慣性が単月の異常を薄める**。

数値で見る。M01/100-0/販社C は §5 のとおり202412に平常の7.5倍（16件）出ているが、
累積使用率はほとんど動かない。累積で数百件ある中の +14件だからである。

→ **これが信号Cが必要な理由**。閾値と信号Cは時間特性が正反対で、補完関係にある。

同時に、累積率は**対策後も下がらない**（累積比なので）。改善確認には使えず、
「要注目ゲート」としてのみ使う、という運用上の性質もここから出る。

## 4. 検出器2：信号B（SF群内ピア比較）

### 4.1 何をしたいのか

CUSUMは「その部品自身の過去」と比べる（自己参照）。だから
**最初から高い水準で平坦に推移する部品は原理的に検知できない**。変化点がないからである。

信号Bは物差しを**他機種**に置く。同じSF-CODE（部品種類）を持つ他の機種と比べて
明らかに高ければ、時間的な変化がなくても異常と判定できる。

### 4.2 集計の作り方（`build_peer_units`）

監視単位は **機種 × (事業, SF)**。部番は合算する。
「機種Aの部番 X-1 と機種Bの部番 Y-3 は同じ部品か」という対応表が不要になるのが利点。

**分子 $C$**：部番も販社も全部足す。

```python
c = (d.groupby(["biz","sf","dev"], as_index=False)
       .agg(C=("use","sum"), nb=("part","nunique"), cover=("elapsed","max")))
```

**分母 $E$**：ここに罠がある。同じ機種で部番が2つあると、素朴に足すと保有台数が2倍になる。

$$E = \sum_{\text{月}} \Big( \sum_{\text{販社}} \max_{\text{部番}} \text{fleet} \Big)$$

```python
fm = (d.groupby(["biz","dev","ym","dist"], as_index=False)["fleet"].max()   # 部番方向に max
        .groupby(["biz","dev","ym"], as_index=False)["fleet"].sum())        # 販社方向は sum
e = fm.groupby(["biz","dev"], as_index=False)["fleet"].sum()                # 月方向に sum
```

**「部番方向は max、販社方向は sum」**。同じ機種の別部番は同じ台数を指しているので
重複、別販社は別の台数なので加算。この非対称性を押さえること。

**経過月を揃える**：`elapsed <= elapsed_cap`（既定36）で切り、
`require_full=True` なら経過月36まで到達している機種だけを比較対象にする。
発売時期の違いがそのまま差になるのを防ぐため。

### 4.3 leave-one-out でピアを作る（`_peer_compare`）

自分自身をピアに含めると、異常な機種は自分で基準を押し上げてしまう。
そこで群の合計から自分を引く。

$$C_{\text{peer}} = \sum_{j \in \text{群}} C_j - C_{\text{self}}, \qquad
E_{\text{peer}} = \sum_{j \in \text{群}} E_j - E_{\text{self}}$$

```python
u["C_peer"] = g["C"].transform("sum") - w["C"]
u["E_peer"] = g["E"].transform("sum") - w["E"]
u["n_peers"] = g["cnt"].transform("sum") - w["cnt"]
```

`transform("sum")` は「グループ合計を各行に配る」操作。ループを書かずに
leave-one-out が1行で書ける定型パターンである。

その後、§2.3 の検定をかける。

```python
u["peer_rate"] = u["C_peer"] / u["E_peer"]      # λ_peer の推定
u["expected"]  = u["peer_rate"] * u["E"]         # 表示用の期待値
u["O_E"]       = u["C"] / u["expected"]
u["p"] = [_cond_binom_p(r.C, r.E, r.C_peer, r.E_peer) for r in u.itertuples()]
```

### 4.4 実測例（M02 / SF-101）

`elapsed_cap=36` での SF-101 群（全機種 nb=1、$E$ が全機種で 179080 と揃っている）。

| 機種 | $C$ | $E$ |
|---|---|---|
| M01 | 174 | 179080 |
| **M02** | **691** | 179080 |
| M03 | 185 | 179080 |
| M04 | 161 | 179080 |
| M05 | 156 | 179080 |
| M06 | 158 | 179080 |
| M07 | 141 | 179080 |
| M08 | 163 | 179080 |
| M09 | 164 | 179080 |

M02 について手計算する。

$$C_{\text{peer}} = 174+185+161+156+158+141+163+164 = 1302, \qquad
E_{\text{peer}} = 8 \times 179080 = 1{,}432{,}640$$

$$\hat\lambda_{\text{peer}} = \frac{1302}{1432640} = 9.088\times10^{-4}$$

$$\texttt{expected} = 9.088\times10^{-4} \times 179080 = 162.75, \qquad
O/E = \frac{691}{162.75} = \mathbf{4.25}$$

検定は

$$n = 691 + 1302 = 1993, \qquad
\pi = \frac{179080}{179080 + 1432640} = \frac{1}{9} = 0.1111$$

$$p = P(X \ge 691), \quad X \sim \mathrm{Bin}(1993,\ 1/9)$$

$H_0$ のもとでの期待は $n\pi = 221.4$、標準偏差は $\sqrt{n\pi(1-\pi)} = 14.0$。
観測691は $(691-221.4)/14.0 \approx 33\sigma$ 上。実際の出力は

$$p = 1.05 \times 10^{-169}$$

生スコアは $\log p/\log\alpha = (-389.1)/(-5.298) = 73.4 \to 3.0$（上限クリップ）。

**他機種は全部沈黙する**：M03 は $C=185$、$O/E = 1.16$、$p = 0.036 > 0.005$ で発火しない。
16%高い程度は、この $E$ の大きさでも偶然の範囲、という判断である。

### 4.5 2パス（`two_pass`）

同じ群に異常機種が複数いると、ピア平均が押し上げられて互いに打ち消し合う。
そこで**1パス目で発火した機種をピアプールから外して再計算**する。

```python
bad = (u["p"] <= alpha_peer) & (u["C"] >= min_count) & (u["O_E"] > 1.0)
...
u2 = _peer_compare(u0, key, min_peers, exclude=flag.to_numpy())
```

`exclude=True` の機種は $C, E, \text{cnt}$ をすべて0にしてピア集計から消える。
ただし**自分自身の判定は行われる**（$u$ の行としては残る）。

§4.4 の出力で M02 だけ `n_peers=8`、他は `n_peers=7` になっているのがこの証拠。
M02 は1パス目で発火したので、2パス目では他機種のピアプールから除外されている。

副次効果として、「新常態受容」で既知の高水準と認めた機種も自動的にピアから外れる。

### 4.6 nb（機種×SF内の部番数）層別

同じ修理で複数部番を使う設計だと、件数が系統的に膨らむ。
素直に「nbで割る」正規化を検討したが、実データでは成立しなかった。

| nb | nb=1 機種基準の交換率比 | ÷nb（残差） |
|---|---|---|
| 2 | 1.39 | 0.69 |
| 3 | 3.66 | 1.22 |
| 4 | 5.09 | 1.27 |

比例していない。しかも nb=3、nb=4 は nb を**超えている**。解釈は因果の逆流である。

> 交換が多い部品 → 設計変更・改良品番の追加 → 部番数が増える

つまり nb は設計属性であると同時に**不具合の結果**でもある。nb で割る行為は
異常の証拠を割り算で消すことになる。

→ 結論：**nb が一致する機種同士だけを比較する**（`nb_strat=True`）。

```python
key = ["biz", "sf", "nb"] if nb_strat else ["biz", "sf"]
```

代償として、nb がばらつく群ではピアが `min_peers` に足りず判定対象から外れる。
シミュレーションの X5（M04/SF-104）が意図的にこの穴を再現している。
**信号Bが沈黙する構造的な穴があることを知っておくこと。**

### 4.7 部番への展開（`candidates_signal_b`）

信号Bの単位は「機種×SF」だが、台帳のキーは部番である。
このまま統合すると、同じ部品が「閾値の行」と「信号Bの行」で2回出てしまう。

そこで発火した (機種, SF) を**実績のある実部番に展開**してから統合する。

```python
pu = (d.groupby(["biz","dev","sf","part"], as_index=False)["use"].sum()
        .rename(columns={"use": "部番使用数"}))
m = a.merge(pu, on=["biz","dev","sf"], how="left")
m = m[m["部番使用数"].fillna(0) > 0]      # 実績ゼロの部番は落とす
```

## 5. 検出器3：信号C（販社別の月次急増）

### 5.1 何をしたいのか

「特定の国で、その部品が突然増えた」を拾う。閾値が構造的に取りこぼす領域（§3.3）を埋める。

2つの設計判断がある。

1. **販社を合算しない**。監視単位は 機種×部番×販社。1国だけ3倍でも、
   他4国が平常なら合算では埋もれる。
2. **ベースラインは直近12ヶ月のローリング窓**。「過去1年の交換率と比べて突然増えた」
   という定義に合わせる。

### 5.2 検定式

判定月 $t$ について、

- 当月：$x_t$ 件、露出 $e_t$（その月の累積販売台数）
- ベースライン窓：直近 $L$ ヶ月（既定12、**当月は含まない**）の $C = \sum x_s$、$E = \sum e_s$

$H_0$：当月のレート ＝ ベースラインのレート。§2.3 をそのまま適用して

$$n = x_t + C, \qquad \pi = \frac{e_t}{e_t + E}, \qquad p = P(X \ge x_t),\ X \sim \mathrm{Bin}(n,\pi)$$

信号Bとの違いは $e_1, e_2$ に何を入れるかだけ。**式は完全に同一**である。

### 5.3 累積和による窓集計（`_rolling_test`）

窓ごとに毎回 `sum` を取ると $O(nL)$ かかる。累積和を先に作れば差で取れて $O(n)$。

```python
cu = np.concatenate([[0.0], np.cumsum(use)])
cf = np.concatenate([[0.0], np.cumsum(fleet)])
...
a = max(0, t - base_len)
C = cu[t] - cu[a]     # 添字 a..t-1 の和 ＝ 当月 t を含まない
E = cf[t] - cf[a]
```

先頭に0を挿しているので `cu[t] - cu[a]` が区間 $[a, t)$ の和になる。
**当月 $t$ が含まれない**のが要点。含めると自分自身で基準を押し上げてしまう。

### 5.4 ガード条件

```python
if t - a < min_base_months:        continue   # 窓が6ヶ月未満 → 判定しない
if E <= 0 or C < min_base_count:   continue   # ベースラインが薄すぎる → 判定しない
if use[t] < min_count or use[t] <= exp: continue  # 上振れ＆最低件数を満たさない → 検定しない
```

- `min_base_months=6`：販社別の行は「その販社で修理が1件でも入るまで生成されない」ため、
  系列の左端が打ち切られている。立ち上がり直後の不安定な露出で判定しないためのガード。
- `min_count=3`：期待値が極小のとき、たまたま2〜3件出ただけで鳴るのを防ぐ。
- `use[t] <= exp` で早期リターン：下振れの月は検定不要（片側検定なので $p$ は大きいに決まっている）。
  **高速化のためであり、判定結果は変わらない。**

### 5.5 実測例（M01 / 部番100-0 / 販社C）

| 年月 | use | fleet |
|---|---|---|
| 202312 | 3 | 1410 |
| 202401 | 1 | 1436 |
| … | … | … |
| 202411 | 1 | 1696 |
| **202412** | **16** | **1722** |

ベースライン窓は 202312〜202411 の12ヶ月。

$$C = 3+1+1+1+0+4+2+4+1+3+2+1 = 23, \qquad E = 18{,}636$$

$$\hat\lambda_{\text{base}} = \frac{23}{18636} = 1.234\times10^{-3}$$

$$\texttt{expected} = 1.234\times10^{-3} \times 1722 = 2.13, \qquad O/E = \frac{16}{2.13} = \mathbf{7.53}$$

検定は

$$n = 16 + 23 = 39, \qquad \pi = \frac{1722}{1722 + 18636} = 0.0846$$

$$p = P(X \ge 16),\ X \sim \mathrm{Bin}(39,\ 0.0846) = 3.87\times10^{-8}$$

$H_0$ のもとでの期待は $n\pi = 3.30$ 件。16件は極端に多い。
生スコアは $\log(3.87\times10^{-8})/\log(0.005) = 17.07/5.30 = 3.22 \to 3.0$（クリップ）。

**$n$ がわずか39しかない点に注目**。ベースラインが薄いので、$O/E$ が7.5倍あっても
二項の裾は素朴なポアソン検定より厚い。この保守性が §2.3 の狙いである。

### 5.6 既知の性質（バグではない）

緩やかな上昇トレンドがあると、ローリングベースラインが遅れて追随するため、
上振れした月で鳴りやすい。合成テストで再現済み（判定500行で2件＝$\alpha=0.005$ の設計値どおり）。

緩やかな上昇は閾値／CUSUMの担当なので、運用では「単月か継続かを目視で切り分ける」で足りる。

### 5.7 件数爆発への注意（最優先の未実施項目）

実データは 3086単位 × 5販社 ≈ **15,000系列**を毎月検定する。
$\alpha = 0.005$ なら期待誤報数は概算で $15000 \times 0.005 = 75$ 件／月。
top_n=15 を単独で食い潰す。実データ投入前に $\alpha$ を絞る実測が必要
（引き継ぎ資料 §4.4）。

> 多重比較の問題である。個々の検定を $\alpha$ で行うと、系列数 $m$ に対して
> 誤報の期待値は $m\alpha$ に比例する。$\alpha$ を下げるか、
> Bonferroni 的に $\alpha/m$ とするか、上位N件で運用側から抑えるかの選択になる。
> 本システムは「$\alpha$ を実測で絞る＋上位N件キャップ」を採る。

## 6. 統合インボックス

### 6.1 統合注目度

3つの検出器のスコアは尺度が違う（閾値は「何倍」、信号B・Cは「αの何乗」）。
そこで全部 0〜3 のレンジに揃えてから統合する。

$$\text{統合注目度} = \max_{d \in \text{発火した検出器}} (\text{生スコア}_d)
+ \beta \cdot (\text{検出器数} - 1), \qquad \beta = 0.5$$

```python
g["統合注目度"] = (g["最大スコア"] + cfg["multi_bonus"] * (g["検出器数"] - 1)).round(3)
```

- **max を取る**：和にすると検出器数が多いだけで上に来る。「一番強い証拠」を代表にする。
- **multi_bonus**：複数検出器の同時発火は真陽性率が高いはずなので加点する。

### 6.2 実測例：初回runの全出力

`python run_month.py panel_初回.csv 台帳_空.xlsx`（閾値5.0%、$\alpha=0.005$）

| 順位 | 機種 | 部番 | 検出器 | 統合注目度 | 内訳 |
|---|---|---|---|---|---|
| 1 | M02 | 101-0 | 閾値/信号B | **3.500** | 累積率11.60%、SF-101 O/E=4.25 |
| 2 | M06 | 102-0 | 閾値/信号B | 3.500 | 累積率7.49%、SF-102 O/E=2.48 |
| 3 | M01 | 100-0 | 信号C | 3.000 | 販社C O/E=7.53、p=3.9e-08 |
| 4 | M04 | 104-1 | 閾値 | 1.731 | 累積率8.66% |
| 5 | M04 | 104-0 | 閾値 | 1.676 | 累積率8.38% |
| 6 | M04 | 104-2 | 閾値 | 1.646 | 累積率8.23% |

### 6.3 台帳による抑制（`LedgerView`）

閾値・信号B・信号Cは**状態を持たない**（CUSUMのようにSを積まない）ので、
台帳の役割は3つに縮退する。

| 役割 | 処置区分 | 効果 |
|---|---|---|
| 終了 | 監視終了 / 機種終了 | 以後ずっと出さない。**部品単位・全検出器** |
| 抑制 | 対策中・ノイズ等 | 再評価年月まで消し込む。**検出器ごとに独立** |
| 基準上書き | 新常態受容 | 閾値 X を引き上げる |
| （例外） | 保留 | 率に関係なく**毎月出し続ける**（放置の検知漏れ防止） |

抑制期間は台帳の「再評価年月」が空欄なら既定値を使う。

```python
"suppress_months": {"閾値": 6, "信号B": 12, "信号C": 3, "CUSUM": 1}
```

信号Bが12ヶ月と長いのは、経過月0〜cap の**累積** O/E が月次でほぼ動かないため。
短くすると同じ機種が毎月鳴り続ける。

**抑制が検出器ごとに独立であることが設計の要**。信号Bを12ヶ月抑制しても、
その間に販社で急増が起きれば信号Cは出る。部品単位にすると12ヶ月間すべての検出器が
盲目になり危険（設計途中で踏んだ穴）。

判定コードは `LedgerView.status(biz, dev, part, detector)`。
`detector=None` なら終了・保留だけを見る共通判定になる。

## 7. 参考：CUSUMとの対比

方針転換により本線からは外れたが、シャドー実行が続いているので理屈を押さえておく。

### 7.1 CUSUMの式

$$S_t = \max\big(0,\ S_{t-1} + x_t - k_t\big), \qquad
k_t = \frac{(R-1)\,\lambda_{0,t}\, f_t}{\ln R}$$

$S_t \ge h$ で発火。$R$ は「検知したい悪化倍率」（例 2.0 = レート倍化）、$h$ は感度。

```python
# cusum_monitor.poisson_cusum()
k = (R - 1.0) * lam0_safe * fleet / log_ratio
for t in range(n):
    s = max(0.0, s_prev + usage[t] - k[t])
```

### 7.2 $k_t$ はどこから来たか

ポアソンの尤度比の対数を取る。$\mu_0 = \lambda_0 f$、$\mu_1 = R\mu_0$ として

$$\log \frac{P_1(x)}{P_0(x)} = x \log\frac{\mu_1}{\mu_0} - (\mu_1 - \mu_0)
= x \ln R - (R-1)\lambda_0 f$$

これを $\ln R$ で割ると $x - k_t$ になる。つまり CUSUM の増分は
**「悪化しているという仮説を、していないという仮説より支持する度合い」を対数尤度比で測り、
$\ln R$ で正規化したもの**である。累積して閾値を超えたら発火。

$\max(0, \cdot)$ は「正常が続く限り証拠を溜め込まない」ためのリセット。

### 7.3 なぜ本線から外したか

- **自己参照型の構造的盲点**：$\lambda_0$ が自分の過去から推定されるので、
  最初から高い水準で平坦な部品は「変化がない」＝沈黙する。
  過去に人が見つけていた例はここに集中していた。
- **露出の過大評価**：監視範囲が経過月60上限で、退役を考慮しない累積販売台数を
  分母に使う。$f_t$ が実態より大きいと $k_t$ が膨らみ、増分 $x_t - k_t$ が
  負に引かれて真の異常を見逃す。
- 結果、過去例を拾おうとすると多数の部品が発火し、triage予算に収まらなかった。

信号B・Cは**比の形**なので、露出定義の偏りが分子分母で相殺されやすい。
これが横断比較の副次的な利点である。

### 7.4 補完関係と共通の限界

| | 得意 | 苦手 |
|---|---|---|
| CUSUM（時系列） | 変化点のある緩やかな劣化 | 最初から高い水準で平坦 |
| 信号B（横断） | 平坦だが同型比で高い | **比較群全体が汚染されている場合** |

同SF群の全機種で同じ部品が不良なら差が出ないので信号Bは沈黙する。
全社共通部品の不良はCUSUM側（時系列の変化点）でしか拾えない。
**2軸は補完関係にあり、片方だけでは穴が残る。**
