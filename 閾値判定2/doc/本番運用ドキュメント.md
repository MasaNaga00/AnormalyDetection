## 1-2. パネルの投入前チェック

- [ ] `累積販売台数` の逆転（`cummax` 補正は自動で入る）
- [ ] **ALL行と販社別合計が一致するか**

```python
import pandas as pd, settings as st
raw = pd.read_csv("panel.csv", encoding="utf-8-sig")
raw[st.COLS["ym"]] = raw[st.COLS["ym"]].astype(str).str.replace(r"\D","",regex=True).astype(int)
key = [st.COLS["biz"], st.COLS["dev"], st.COLS["part"], st.COLS["ym"]]
a = raw[raw[st.COLS["dist"]].astype(str) == st.ALL_TOKEN].groupby(key)[st.COLS["monthly_use"]].sum()
b = raw[raw[st.COLS["dist"]].astype(str) != st.ALL_TOKEN].groupby(key)[st.COLS["monthly_use"]].sum()
m = a.rename("all").to_frame().join(b.rename("sum"), how="inner")
print(f"不一致: {int((m['all'] != m['sum']).sum())} / {len(m)} 行")
```

一致しなければ ALL は別ソース。分子の欠け方が販社別行と違うので、
**閾値検出器の扱いを別途相談する**。リハーサルの前提が崩れる唯一の箇所。

# 第2部 月次サイクル

毎月やることは5つ。慣れれば30分〜1時間。

```bash
python run_month.py panel.csv 台帳.xlsx
```

## ① 受領状況を見る（発火件数より先に）

```
=== 販社の報告遅れ（global horizon = YYYYMM）===
販社  最終年月  痩せ比  採用margin  horizon  遅れ月数  判定
```

- **`判定=再評価窓不足`** → `C_REVISIT_MONTHS` を上げる。放置するとその販社の月が永久に未検定
- **`採用margin` が 2以上** → 自動判定が暴れている。`HORIZON_MARGIN_OVERRIDES` で固定
- **`遅れ月数` が普段より大きい** → 販社側の運用が変わった可能性。確認する

受領状況そのものが業務情報になる。「D社が3ヶ月遅れている」は
検知以前に是正すべき事実。

## ② 上位15件をレビュー

`出力/YYYYMM/レビュー用_YYYYMM.csv`

**`遅延月` で降順ソートすると、報告遅れで今回はじめて判定できた行がまとまる。**
これらは過去の事象なので、現在進行形の異常とは緊急度が違う。区別して扱う。

判断のとき見るもの:

| 見るもの | 意味 |
|---|---|
| `検出器` | 複数そろっていれば真陽性率が高い |
| `統合注目度` | 並び順。3.0が各検出器の上限、+0.5×(検出器数-1) |
| `指標` | 各検出器の生の数字 |
| `対象月内訳` | 複数月にまたがっているか |
| `遅延月` | >0 なら過去の事象 |

**信号Bの沈黙は「正常」の証拠ではない。** `信号B詳細_YYYYMM.csv` に
その機種×SFの行が無ければ「監視できていない」であって「正常」ではない。
nb層別でピアが足りない群がこれに当たる（1-5 の `nb_profile` で把握済みのはず）。

## ③ 台帳に追記

レビュー用CSVの **A〜F列を台帳のB〜G列に貼る**（並びが一致している）。

| 台帳の列 | 記入 |
|---|---|
| A 記録日 | 手入力 |
| B〜G | レビュー用CSVから貼り付け |
| H 処置区分 | ドロップダウンから選択 |
| I 再評価年月 | 空欄なら検出器ごとの既定月数 |
| J 上書き閾値 | 新常態受容のときだけ。`提案Y下限` を写す |
| K〜O | 空欄（CUSUM専用） |
| P 原因メモ | `指標` を貼っておくと後で効く |
| Q 確認者 | 手入力 |

**厳守2点。**

- **`判定年月` は書き換えない。** run年月に直すと次回runで抑制が効かず二重に出る
- **`検出器` を必ず埋める。** 空欄は「全検出器」扱いになり、抑制が広がる

## ④ 台帳をバックアップ

- [ ] 日付つきでコピー（`台帳_20260501.xlsx`）

# 運用ガイドに明記する既知の穴

現場が「バグだ」と受け取らないよう、先に共有しておく。

| 現象 | 性質 |
|---|---|
| nb混在群の機種が信号Bで沈黙 | 構造的。ピアが足りない。閾値側で拾う |
| 同SF群の全機種が不良だと信号Bが沈黙 | 横断比較の原理的限界。時系列側でしか拾えない |
| 緩やかな上昇トレンドで信号Cが鳴る | ローリングベースラインが遅れて追随。単月か継続かを目視で切り分け |
| 累積使用率が実際より低く出る | 報告遅れで分子だけ欠ける。見逃し方向のみ。翌月自動是正 |
| 経過月が小さい部品が上位15件に入りにくい | 検知はできているが順位で沈む |
| 遅れて届いた月の異常が数ヶ月後に出る | 仕様。`遅延月` 列で区別する |
| 処置区分の誤字がエラーにならない | 静かに違う挙動になる。ドロップダウンで防ぐ |
