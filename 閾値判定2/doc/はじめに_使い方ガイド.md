# はじめに — 使い方ガイド（部品出庫異常検知）

**初めて使う人はこのファイルから読む。** 毎月の運用に必要なことはここで完結する。
細かい理由・設計の経緯は末尾「11. 次に読む資料」の各資料へ。

---

## 1. このシステムがやること

修理部品の出庫データ（パネル）から「通常より多く出ている部品」を毎月見つけ、
**詳しく修理状況を確認すべき候補を上位15件に絞って**出す。3つの検出器で見る。

| 検出器 | 見るもの | 得意なもの |
|---|---|---|
| **閾値** | 累積使用率が基準X%を超えたか | 最終的に高くなる部品（確実だが遅い） |
| **信号B** | 同じ部品種類（SF）の他機種と比べて高いか | 閾値に届かないが同型比で高い部品 |
| **信号C** | 特定の販社（国）で、その月だけ急に増えたか | 突発的な急増 |

人がレビューして**台帳**に判断を書くと、翌月以降はその判断に従って消し込み・再表示される。
結果は毎回「パネル＋台帳」から作り直すので、何度実行しても同じ入力なら同じ結果になる。

```
閾値判定2/                        ← プログラム一式。**必ずこのフォルダで実行する**

├─ categories/                    カテゴリごとの設定（違う値だけ書く）
│   ├─ _テンプレート.py            コピー元（_ で始まるものは一括実行の対象外）
│   ├─ カメラ.py
│   └─ レンズ.py
├─ run_all.py                     ★毎月これを実行（全カテゴリ一括）
├─ run_month.py                   1カテゴリだけ実行するとき
├─ 検出時期確認/                  過去の異常部品が「いつ検出できたか」を調べるツール（7.1）
├─ （その他のプログラム）
├─ data/                          入力パネル（置き方は 3.2）
├─ 台帳/                          カテゴリごとの台帳（Excel）
├─ doc/                           ドキュメント
└─ 出力/

    │   ├─ チューニング/           操作点決めの中間ファイル

    ├─ レンズ/ …
    └─ _バッチログ/                run_all の実行ログ
```

`data/` と `台帳/` の名前・場所は自由（カテゴリ設定に書いたパスが使われる）。上は推奨例。

## 3. 初回の準備（カテゴリごとに1回）

### 3.1 カテゴリ設定を作る

`categories/_テンプレート.py` をコピーして `categories/レンズ.py` のように名前を付ける。
**ファイル名がそのままカテゴリ名**（出力フォルダ名・ファイル名の末尾）になる。

```python
from settings import *          # ← 消さない（共通の設定を読み込む）

PANEL_PATH  = "data/*/レンズ.csv"      # 入力パネル（3.2）
LEDGER_PATH = "台帳/台帳_レンズ.xlsx"  # 台帳（3.3）
EXPECT_BIZ  = {"E1"}                   # このカテゴリの事業コード（取り違え防止）

# ここから下は settings.py と違う値だけ書く
BASE_THRESHOLD_PCT = 3.0
```

書き方のきまり:

- **書かなかった項目は `settings.py` の値になる。** 全カテゴリ共通の変更は `settings.py` を直す
- 辞書を一部だけ変えるときは `COLS = {**COLS, "sf": "SFコード"}` のように書く
- パスはプログラムのフォルダからの相対、または絶対パス
- `EXPECT_BIZ` にない事業コードがパネルに混ざっていると、実行は**停止**する。
  別カテゴリのファイルを渡してしまう事故を防ぐため。必ず書く

### 3.2 入力パネルの置き方

`PANEL_PATH` の書き方で運用を切り替える。

| 運用 | 置き方 | PANEL_PATH |
|---|---|---|
| **立ち上げ期**：月ごとにフォルダ | `data/202501/レンズ.csv` | `"data/*/レンズ.csv"` |
| **安定運用**：同じ名前で上書き | `data/レンズ.csv` | `"data/レンズ.csv"` |

- `*` があると、一致したファイルのうち**名前順で最後（＝最新月）**を使う
- **月のフォルダ名は `YYYYMM` の6桁**で揃える（`2025-1` などが混ざると順番が崩れる）
- 安定運用に移るときは、カテゴリ設定の `PANEL_PATH` を1行書き換えるだけ
- パネルは加工せずそのまま置いてよい（年月の書式変換・累積台数の補正は自動）

### 3.3 台帳を用意する

1. `台帳テンプレート_統合版.xlsx` をコピーして `台帳/台帳_レンズ.xlsx` にする
2. `選択肢` シートに8つの処置区分を入れ、処置区分の列（I列）にドロップダウンを設定
   ```
   対策中 / 新常態受容 / ノイズ / 感度上書き / スパイク確認 / 保留 / 監視終了 / 機種終了
   ```
   **誤字はエラーにならず静かに違う動きになる**（例: `監視終了` の打ち間違い → 終了されず数ヶ月後に復活）。
   ドロップダウンが唯一の防止策
3. **台帳はカテゴリごとに別ファイル。** 共有すると別カテゴリの判断で消し込まれる
4. 台帳には `部番` の右に **`部品名`** の列がある（表示用。判定には使わない）

**2026-10 より前に作り始めた台帳**（`部品名` 列が無いもの）は、Excel で
**`部番`（D列）の右に列を1つ挿入し、見出しを `部品名` にする**。Excel の列挿入なら
処置区分のドロップダウンも一緒に右へずれる。部品名の中身は空欄のままでよい
（過去の行を埋める必要はない）。列が無いまま実行すると
`[注意] 台帳に「部品名」列がありません` と出る。

### 3.3b 部品名の列

パネルに部品名の列があれば、統合インボックス・レビュー用CSV・信号C詳細の
**`部番` の右に `部品名`** が付く。列名は `COLS["part_name"]`（既定 `"部品名"`）。
違う列名ならカテゴリファイルに `COLS = {**COLS, "part_name": "品名"}` のように書く。

- 名前は **機種×部番** ごとに引く（同じ部番でも機種で名前が違ってよい）
- 月によって表記が変わる場合は**最新月の値**を使う
- パネルに列が無い・値が空の部番は空欄で出る（処理は止まらない）

### 3.4 設定とデータを確認する

```bash
python check_settings.py --cat レンズ     # どの設定・パネル・台帳・出力先が使われるか
python check_panel.py --cat レンズ        # パネルの中身のチェック（8項目）
```

`check_panel` で `✗ 要対処` が出たら元データを直す（詳細は `本番運用ドキュメント.md` 1-2）。

### 3.5 操作点（感度）を決める — 実データ投入時に1回

合成データで決めた既定値のままだと件数が合わない。**信号Cは省略不可**。

```bash
python tune_c_alpha.py --cat レンズ      # 信号C の件数を実測
python tune_b_minoe.py --cat レンズ      # 信号B の件数を実測
```

結果を見て、カテゴリ設定に値を書く（例: `C_MIN_OE = 4.0`、`B_MIN_OE = 2.0`）。
中間ファイル（`scan_c.csv` / `scan_b.csv`）は `出力/レンズ/チューニング/` に保存される。
読み方と判断基準は `本番運用ドキュメント.md` 1-5。

## 4. 毎月やること

### ① パネルを置く

立ち上げ期なら `data/202502/` フォルダを作って各カテゴリのCSVを置く。

### ② 一括実行する

```bash
python run_all.py
```

最後に結果の一覧が出る。

```
カテゴリ  結果  判定年月  発火  時間  注意・エラー
カメラ    成功  202502      18    5s
            パネル: data/202502/カメラ.csv
レンズ    成功  202502      12    4s
            パネル: data/202502/レンズ.csv
```

**ここで確認すること:**

- `結果` がすべて `成功` か（`★失敗` は下の「困ったとき」）
- `パネル:` が**今月のファイル**か
- `注意・エラー` に `★同じ判定年月を再実行` が出ていないか → 今月のパネルを置き忘れている

1つのカテゴリが失敗しても残りは実行される。全出力は `出力/_バッチログ/` に残る。

### ③ 受領状況を見る

各カテゴリの画面出力（またはログ）の `=== 販社の報告遅れ ===` の表を見る。

- `判定=再評価窓不足` → カテゴリ設定の `C_REVISIT_MONTHS` を上げる（放置するとその販社の月が永久に未検定）
- `遅れ月数` がいつもより大きい → 販社側の送付が遅れている。それ自体が業務情報

### ④ 上位15件をレビューする

`出力/レンズ/202502/レビュー用_202502_レンズ.csv` を開く。

| 列 | 見方 |
|---|---|
| `検出器` | 複数そろっていれば本物の可能性が高い |
| `統合注目度` | 並び順。各検出器3.0が上限、検出器が1つ増えるごとに+0.5 |
| `指標` | 各検出器の生の数字 |
| `遅延月` | >0 なら過去の月の発火（報告遅れで今回判定できた月、または再評価窓で残っている月） |
| `対象月内訳` | 発火した月の一覧 |

原因を詳しく見るときは同じフォルダの `信号B詳細_…csv` / `信号C詳細_…csv`。

### ⑤ 台帳に記入する

レビュー用CSVの **A〜G列（事業コード〜判定年月。部品名を含む）をそのまま台帳のB〜H列に貼り**、処置区分（I列）を選ぶ。

**厳守2点:**

- **`判定年月` は書き換えない。** 今月に直すと次回の実行で消し込みが効かず二重に出る
- **`検出器` を必ず埋める。** 空欄は「全検出器」扱いになり、消し込みが広がりすぎる

`再評価年月` が空欄なら、検出器ごとの既定期間（閾値6・信号B12・信号C3ヶ月）だけ消し込む。
処置区分の意味は `本番運用ドキュメント.md` 第2部 ③。

### ⑥ 台帳をバックアップする

日付つきでコピー（`台帳_レンズ_20250305.xlsx` など）。**台帳は再現できない唯一のデータ。**

### ⑦ Tableau を更新する

`出力/*/*/統合インボックス_*.csv` をワイルドカードでユニオンすれば全カテゴリをまとめて見られる
（各CSVの末尾に `カテゴリ` 列がある）。

## 5. 1カテゴリだけ・試しに回すとき

```bash
python run_month.py --cat レンズ                     # 1カテゴリだけ
python run_all.py カメラ レンズ                       # 指定したカテゴリだけ
python run_month.py data/試し.csv 台帳/台帳_レンズ.xlsx --cat レンズ --no-snapshot
```

- パネル・台帳を引数で渡すとそちらが使われる（設定と違えば注意が出る）
- **試し実行・切り出したパネルでは `--no-snapshot` を付ける。**
  付けないと、その月の正規のスナップショットが試しのデータで置き換わる
- 同じ月を何度実行しても結果は変わらない。ただし**レビュー中に再実行しない**
  （レビュー用CSVの行が変わり、台帳に写し間違える）

## 7. チューニング・調査のツール（全ツール `--cat` 対応）

パネルの引数は省略するか `-` にすると、カテゴリ設定の `PANEL_PATH` が使われる。

| やりたいこと | コマンド |
|---|---|
| 設定の確認 | `python check_settings.py --cat レンズ` |
| パネルの点検 | `python check_panel.py --cat レンズ` |
| 信号Cの操作点 | `python tune_c_alpha.py --cat レンズ`（ラベルありは `python tune_c_alpha.py - labels.csv --cat レンズ`） |
| 信号Bの操作点 | `python tune_b_minoe.py --cat レンズ`（ラベルありは `- labels.csv` を付ける） |
| 過去例が上位15件に入るか | `python check_rank.py --cat レンズ labels.csv` |
| ラベルが無いときの検出力 | `python inject_power.py --cat レンズ`（信号Bは末尾に `b`） |
| 信号Cで「なぜ出ない」 | `python diagnose_signal_c.py - M02 101-0 D 202410 --cat レンズ` |
| 過去の異常部品が**いつ検出できたか** | `python 検出時期確認/trace_detection.py M02 101-0 --cat レンズ`（7.1） |
| 信号Bで**なぜその部番が鳴ったか** | `python 検出時期確認/explain_signal_b.py M02 101-0 --cat レンズ`（7.2） |

### 7.1 過去の異常部品が「いつ・どの検出器で」検出できたかを調べる

機種と部番を指定すると、月ごとに「その月に実行していたら鳴ったか」を再現し、
閾値・信号B・信号Cそれぞれの**初検出月**と、鳴らなかった月の**理由**を出す。

```bash
python 検出時期確認/trace_detection.py M02 101-0 --cat レンズ                    # 1部品
python 検出時期確認/trace_detection.py M02 101-0 --from 202301 --to 202412 --cat レンズ
python 検出時期確認/trace_detection.py --list 対象一覧.csv --cat レンズ            # まとめて
python 検出時期確認/trace_detection.py M02 101-0 --biz E1 --panel panel.csv       # 事業コード・パネルを指定
```

画面の要約:

```
検出器   初検出  経過月  鳴った月数  そのときの値
 閾値    202209    18       28    累積率5.25% / 閾値5.00%
信号B    202404    37        9    SF-101 O/E=3.85（ピア2機種）
信号C    202209    18        1    販社C O/E=3.30 使用10件
→ 最も早い検出: 202209（閾値/信号C）
```

- `--list` の CSV は `開発コード, 部番` の2列（`事業コード` もあれば使う）。
  **`発生年月`（YYYYMM）の列を入れると、発生の何ヶ月前に検出できたか（先行月数）も出る**
- 結果は `出力/レンズ/検出時期確認/` に保存される
  - `検出時期_<機種>_<部番>.csv` … 月ごとの値・判定・理由（Tableau でそのまま折れ線に）
  - `検出時期_<機種>_<部番>_信号C販社別.csv` … 信号Cの販社×月の明細
  - `検出時期_要約.csv` … `--list` のとき、部品ごとの初検出月
- 鳴らなかった理由の例: `窓未完走（経過月20<36）`（信号Bは発売36ヶ月まで判定しない）、
  `ピア不足`、`O/E1.9<3.0`、`累積率4.2%<5.0%`、`SFは発火・この部番はシェア5%<10%で非表示`
- `--from` の開始月にすでに鳴っていた検出器には「期間の開始時点ですでに発火中」と出る
  （本当の初検出月は `--from` を外すと分かる）

**前提（結果を読むときの注意）**

- 台帳・top_n は使わない（消し込み無しで「検出器が鳴ったか」だけを見る）
- 設定（閾値・`min_oe` など）は本番と同じカテゴリ設定を使う
- **今のパネルで過去を再計算する。** 過去の月は当時より修理データが出そろっているので、
  実運用より**早めに**検出されて見えることがある
- **販社の報告遅れは考慮しない**（データが揃っていた場合の最速の検出月）。実運用ではその分遅れる

### 7.2 信号Bで「なぜこの部番が鳴ったのか」を調べる

「経過月×累積使用率で同じSFの部品を並べると、他機種より低く見えるのに信号Bで鳴る」
ようなときに使う。信号Bは**プロットとは別の物差しで、別の相手と**比べているので、
その違いのどれが効いたかを分解して見せる。

```bash
python 検出時期確認/explain_signal_b.py M02 101-0 --cat レンズ
python 検出時期確認/explain_signal_b.py M02 101-0 --asof 202406 --cat レンズ   # 過去の月で
```

画面には3つの表が出る。

**① 比較の内訳** … 同じSFの全機種について、比較相手に入ったか（入らない理由）と2つの物差し

| 列 | 意味 |
|---|---|
| `比較の扱い` | `○比較相手` / `×窓未完走` / `×nb違い` / `×1回目で発火→比較から除外` |
| `累積使用率@cap` | プロットの物差し（経過月36時点の 件数÷販売台数） |
| `台数×月あたり率` | **信号Bの物差し**（件数÷台数×月の合計） |
| `平均在籍月数` | 台数×月÷販売台数。**小さいほど販売が窓の後半に偏っている** |
| `基準への重み` | 比較相手の基準に占める割合。大きい機種が基準をほぼ決める |

**② SF内の部番** … 信号BはSF内の全部番を合算して判定する。部番が途中で切り替わった機種は、
1本ずつの線が低くても合計では高いことがある

**③ 見方を変えたときのO/E** … プロットとの違いを1つずつ外したら鳴るか。
**「鳴らない」になった見方が、鳴った理由**。最後の行にまとめが出る

```
                    見方   O_E   判定
              実際の信号B 1.800   鳴る
     4を外す: 2パス目の除外なし 1.200 鳴らない   ← 高い機種が比較から外れて基準が下がった
    2を外す: 分母を累積販売台数に 1.800   鳴る
    1を外す: この部番だけで比べる 0.827 鳴らない   ← 旧部番と合算すると高い
→ 次の違いを外すと鳴らなくなる: 4を外す / 1を外す
```

| 番号 | プロット | 信号B |
|---|---|---|
| 1 | 部番ごとの線 | SF内の全部番を合算 |
| 2 | 分母が累積販売台数 | 分母が台数×月（市場に置かれていた量） |
| 3 | 同SFの全機種 | 同じnbで経過月36まで完走した機種だけ |
| 4 | — | 1回目で鳴った機種を比較から外す（2パス） |
| 5 | 各機種が同じ重み | 件数合計÷露出合計（台数の多い機種が支配） |
| 6 | 経過月36より先も描く | 経過月0〜36だけ |

**`信号B曲線_<機種>_<部番>.csv`** を Tableau で開くと、機種×部番（と `SF合計`）×経過月で
`累積使用率%`（今のプロット）と `台数×月あたり率%`（信号Bの物差し）を並べて描ける。
`窓内`＝True の範囲・`比較の扱い` で色分けすると、どこで見え方が逆転するかが分かる。

## 8. 困ったとき

| 表示・症状 | 原因と対処 |
|---|---|
| `[停止] 想定外の事業コード…` | 別カテゴリのパネルを渡している。`PANEL_PATH` とファイルの中身を確認 |
| `[エラー] …パターンに一致するファイルがありません` | 今月のフォルダ・ファイル名の綴りを確認 |
| `[エラー] カテゴリ設定が見つかりません` | `categories/<名前>.py` のファイル名と `--cat` の綴りを確認 |
| `[注意] 判定年月 … は実行済み` | 今月のパネルが未配置で前月を再実行している（意図した再実行なら問題なし） |
| `[注意] パネルがカテゴリ設定と違います` | 引数で別ファイルを渡している。意図どおりか確認 |
| `[注意] 台帳に「部品名」列がありません` | 台帳の部番の右に `部品名` 列を挿入（3.3）。しないと貼り付けが1列ずれる |
| `[注意] パネルに部品名の列「…」がありません` | 部品名は空欄で出る。列名が違うなら `COLS["part_name"]` を直す（3.3b） |
| `判定=再評価窓不足` | `C_REVISIT_MONTHS` を表の `遅れ月数` 以上に |
| 設定を変えたのに効かない | `python check_settings.py --cat …` で読まれている設定を確認。Jupyter なら `cl.use()` を呼び直す |
| 件数が多すぎる | 検出器別の内訳を見て、多い検出器の主レバーを上げる（信号B: `B_MIN_OE`、信号C: `C_MIN_OE`） |
| 特定の部品がなぜ出ない／出る | `本番運用ドキュメント.md` 第4部 |
| `USE_HORIZON=False` の注意 | 報告遅れ対応が無効。信号Cが最新月しか見ない。切り分け以外では True に戻す |

## 9. やってはいけないこと

- **`判定年月` の書き換え**、**`検出器` の空欄**（4-⑤）
- **台帳を複数カテゴリで共有する**
- **試し実行で `--no-snapshot` を付け忘れる**
- **レビュー中の再実行**
- **信号Bの感度を `B_ALPHA` で調整する**（効かない。`B_MIN_OE` を使う）
- **`C_MIN_BASE_COUNT` を上げる**（「ほぼゼロ→突然多数」という一番拾いたい形が消える）
- `B_NB_STRAT` / `B_TWO_PASS` / `SUPPRESS_MONTHS["信号B"]` を理由なく変える（実測で決めた値）

## 10. 知っておくべき限界

現場が「バグだ」と受け取らないよう、先に共有しておく。

| 現象 | 性質 |
|---|---|
| 信号Bで沈黙＝正常、ではない | 同じ部番数のピアが足りない機種は監視できていない（`tb.nb_profile()` で一覧） |
| 同SF群の全機種が不良だと信号Bは沈黙 | 横断比較の原理的な限界 |
| 発売12ヶ月以内の機種は拾いにくい | 3検出器とも弱い（未対策の課題） |
| 緩やかな上昇で信号Cが鳴る | ベースラインが遅れて追随するため。単月か継続かを目視で |
| 過去月の発火が数ヶ月出続ける | 再評価窓（既定6ヶ月）の仕様。台帳に記録すれば消える |
| 直近の累積率が低めに出る | 報告遅れの販社がある間。`完全性_…csv` で確認 |
