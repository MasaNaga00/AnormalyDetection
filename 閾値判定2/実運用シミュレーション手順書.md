# 実運用シミュレーション手順書

本番移行の前に、月次運用の一巡（実行 → レビュー → 台帳記入 → 翌月実行）を
手元で体感するための手順。所要 30〜60分。

## 2. レビュー — 1件ずつ判断する

`出力/202412/レビュー用_202412.csv` を Excel で開く。判断に使う列:

| 列 | 見方 |
|---|---|
| **検出器** | どの信号で鳴ったか。複数なら確度が高い |
| **統合注目度** | 並び順の根拠。最大3.0＋検出器ごとに0.5加点 |
| **指標** | 検出器ごとの根拠（累積率／O/E比／p値） |
| **対象販社** | 信号Cならどの販社か |

### 検出器ごとの読み方

**閾値**が鳴った → 累積使用率が基準Xを超えた。**確実だが遅い**。
既に相当数が出た後なので、対策済みか確認する。

**信号B**が鳴った → 同じSF-CODEの他機種と比べて高い。**閾値より早い**。
`出力/YYYYMM/信号B詳細_YYYYMM.csv` で `peer_rate`（ピアの平均レート）と `n_peers`（比較機種数）を
確認する。ピアが2〜3機種しかない群は偶然の可能性を疑う。

**信号C**が鳴った → 特定販社で単月急増。`出力/YYYYMM/信号C詳細_YYYYMM.csv` で
その販社の前後数ヶ月を見て、単発か継続の入口かを切り分ける。
一括交換・在庫調整・報告の遅延まとめ計上なども単月急増として出る。

### 判断できないとき

**「保留」を選ぶ。** 翌月以降も毎月インボックスに出続けるので、忘れない。
これは「黙らせる」のではなく「見え続けさせる」ための区分。

## 3. 台帳に記入する

`出力/YYYYMM/レビュー用_YYYYMM.csv` の行をそのまま台帳（`台帳_空.xlsx` の「台帳」シート）に
貼り付け、以下の列を埋める。

### 必ず埋める

- **処置区分** … 下の8択から
- **記録日** … 記入した日
- **確認者** … 自分の名前

### 必要なときだけ埋める

- **再評価年月** … 空欄なら検出器ごとの既定期間が自動で効く（下表）
- **上書き閾値** … 「新常態受容」のときの新しい基準X（%）
- **原因メモ** … 後から見て分かるように

### 処置区分の8択

| 処置区分 | 意味 | 次に鳴るのは |
|---|---|---|
| **対策中** | 対策を実施中 | 再評価年月に再点灯 |
| **新常態受容** | この水準が正常と認める | 上書き閾値を超えたら |
| **ノイズ** | 異常ではない | 既定期間後 |
| **感度上書き** | この単位だけ感度を変える | （CUSUM用） |
| **スパイク確認** | 単月の急増を確認済み | 既定期間後 |
| **保留** | 判断保留 | **毎月出続ける** |
| **監視終了** | この部品はもう見ない | 二度と出ない |
| **機種終了** | 機種ごと終了（部番="機種全体"） | 二度と出ない |

### 再評価年月を空欄にしたときの既定抑制期間

| 検出器 | 既定 | 理由 |
|---|---|---|
| 閾値 | 6ヶ月 | 累積率は下がらないので、本来は上書き閾値で対応する |
| **信号B** | **12ヶ月** | 経過月0〜36の累積O/Eは月次でほぼ動かない |
| 信号C | 3ヶ月 | 月次のローリング比較なので自然に戻る |
| CUSUM | 1ヶ月 | 台帳リセットで別途処理される |

**抑制は検出器ごとに独立している。** 信号Bを12ヶ月抑制しても、その間に
販社で急増が起きれば信号Cは出る。「監視終了」と「保留」だけが部品全体に効く。

### 記入例

すぐ試したい場合は、用意してある `台帳_記入例.xlsx` を使う。8件それぞれに
異なる処置区分を入れてあるので、抑制の効き方の違いが一度に見られる。

| 機種/部番 | 処置区分 | 再評価年月 | 意図 |
|---|---|---|---|
| M02 / 101-0 | 対策中 | 202506 | 半年後に効果確認 |
| M06 / 102-0 | 保留 | 空欄 | 毎月見続ける |
| M01 / 100-0 | スパイク確認 | 空欄 | 3ヶ月抑制 |
| M04 / 104-1 | 新常態受容 | 空欄（上書き閾値=9.0） | 基準を9%に引き上げ |
| その他4件 | ノイズ | 空欄 | 既定期間で抑制 |

## 4. 翌月実行 — 消し込みを確認する

```bash
python run_month.py panel_翌月.csv 台帳_記入例.xlsx
```

```
=== 判定年月 202501 ／ 発火 4件 ===
  M06 102-0 閾値/信号B  3.500  ← 保留なので毎月出る
  M10 103-0    信号C    3.000  ← 新規。販社Aで急増
  M10 103-1    信号C    3.000  ← 同上（同SFの別部番）
  M04 102-0    信号C    1.014  ← 新規
```

**確認すべきこと（ここが体感の本題）**

1. **8件 → 4件に減った** … 台帳に記録した分が消し込まれている
2. **M06 は残っている** … 「保留」なので毎月出続ける
3. **M02 は消えた** … 「対策中・再評価202506」なので半年間は出ない
4. **M04/104-1 は消えた** … 新常態受容で基準が9%に上がった
5. **M10 の信号C が新規に出た** … 翌月データで起きた急増を捉えている

この5点が確認できれば、月次サイクルは理解できたことになる。

## 5. 答え合わせ

ここで初めて `仕込み一覧.csv` を開く。5つの異常を仕込んである。

拾えたもの、拾えなかったものを確認してほしい。
**X5（M04 / SF-104）は意図的に信号Bで拾えないようにしてある。**
この群は機種によって部番数がばらつく（nb混在）ため、nb層別でピアが足りず
判定対象から外れる。実データの幅≥1の群で同じことが起こる。
閾値でしか拾えないので、発見が遅れる構造的な穴になる。

## 6. 実データに移すときに変えるもの

`run_month.py` の上部だけ。

```python
COLS = dict(biz="事業コード", dev="開発コード", part="部番", dist="販社",
            ym="年月", elapsed="経過月", monthly_use="月次使用数",
            cum_sales="累積販売台数", sf="SF-CODE")     # ← 実データの列名に

CFG.update(
    base_threshold_pct=5.0,   # ← 現行運用の基準Xに合わせる
    c_alpha=0.005,            # ← 要調整。下記参照
    top_n=15,
)

OUT_ROOT = "出力"              # ← 生成物の置き場（共有フォルダなどに変えてもよい）
```

### 実データ投入前に必ず測ること

**信号Cの `c_alpha`。** 3086単位 × 5販社 ≈ 15,000系列を毎月検定するので、
`0.005` のままだと月数十件出る可能性がある。過去24ヶ月で実測してから決める。

```python
import pandas as pd, signal_c_dist as sc, run_month as rm
raw = pd.read_csv("panel.csv", encoding="utf-8-sig")
r = sc.run_signal_c(raw[raw.販社 != "ALL"], rm.COLS, months_back=24, alpha=0.005)
print(r[r.alert_dist].groupby("ym").size())   # 月あたり何件だったか
```

月5件程度に収まる `alpha` まで絞る。同時に、**過去に人が見つけた急増例が
この中に出てくるか**も確認できる。

### CUSUM は裏で回し続ける

triage はしない。発火記録だけ残しておく。半年後に台帳と突き合わせれば
「閾値・信号B・信号Cが拾えず、CUSUMだけが拾っていた件」が見える。
台帳の `検出器` 列が、その評価の土台になる。
